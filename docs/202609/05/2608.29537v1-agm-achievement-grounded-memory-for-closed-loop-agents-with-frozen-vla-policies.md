## 摘要
冻结的视觉-语言-动作（VLA）策略提供广泛的操控技能，但执行开环动作块时不跟踪任务进度，因此智能体无法可靠地决定是继续、重试还是终止。外部记忆是一种自然的补救措施，但当尝试的动作被视为已完成的进度时，它可能是有害的，将局部执行错误转化为持久的任务状态错误。我们提出基于成就锚定的记忆（AGM），一种用于冻结VLA策略的轻量级闭环框架，它将任务表示为带有进度指针的子目标序列，并且仅在当前子目标通过物理证据验证后才推进该记忆。本体感觉交互线索决定何时验证，而连贯点跟踪和语言条件跨视角比较（来源于冻结基础模型，通过单个243万参数的验证头）决定实现了什么。因此，AGM将开环执行转化为执行、验证和进度的闭环，保持策略冻结且无需测试时大模型推理。在RoboMME Counting基准上，AGM在PickXTimes上达到[?]和在BinFill上达到[?]，平均超过最强记忆增强基线[?]个百分点，并且该框架在物理机器人上产生了同样显著的收益。因此，可靠的具身记忆更多地取决于纪律性的状态更新，而非记忆容量。

## Abstract
Frozen vision-language-action (VLA) policies offer broad manipulation skills but execute open-loop action chunks without tracking task progress, so the agent cannot reliably decide whether to continue, retry, or terminate. External memory is a natural remedy, yet it can be harmful when attempted actions are treated as completed progress, turning local execution errors into persistent task-state errors. We propose Achievement-Grounded Memory (AGM), a lightweight closed-loop framework for frozen VLA policies that represents a task as a subgoal sequence with a progress pointer and advances this memory only after the current subgoal is verified by physical evidence. Proprioceptive interaction cues decide when to verify, while coherent point tracking and language-conditioned cross-view comparison, sourced from frozen foundation models through a single 2.43M-parameter verification head, decide what was achieved. AGM thereby converts open-loop execution into a closed loop of execution, verification, and progress, keeping the policy frozen without test-time large-model inference. On the RoboMME Counting benchmark, AGM reaches on PickXTimes and on BinFill, surpassing the strongest memory-augmented baseline by points on average, and the framework yields equally decisive gains on a physical robot. Reliable embodied memory thus depends more on disciplined state updates than on memory capacity.

# AGM: 基于成就锚定的记忆用于冻结 VLA 策略的闭环智能体

## 1. 核心问题与研究动机

- **背景**：大规模视觉-语言-动作（VLA）模型可直接将视觉观察与语言指令映射为连续动作。但由于逐任务微调成本高昂，一种实用路线是**保持策略权重冻结**，通过语言条件子目标组合其固有能力。
- **核心问题**：任务进度（task progress）是一种**隐藏状态**，冻结的 VLA 策略既无法内部表示它，也无法从当前观测中恢复它。在重复性、计数型操作任务中，不同阶段在视觉上互相混淆（perceptual aliasing），策略无法判断自己已完成多少次、是否该终止。
- **已有方案的缺陷**：外部记忆看似是直接解法，但若只是将“每次操作尝试”都记为进度，会带来严重危害——一次失败的抓取被误写为成功，会把**瞬时局部错误固化成持续的任务状态错误**，甚至导致不如完全不用进度记忆。
- **核心洞察**：可靠具身记忆的关键不在“存什么”或“存多少”，而在**“何时才允许写入”**。尝试（attempt）不等于成就（achievement），只有经物理证据验证的执行结果才有资格更新任务状态。

## 2. 方法论

### 2.1 总体框架

- 将任务拆解为带类型的**有序子目标序列** 

  G = {(g_k, c_k)}

  （g_k 为子目标语言指令，c_k 为类型：grasp / place-rev / place-irrev / other）。
- 维护极简任务记忆 **M_t = (G, p_t)**，其中 p_t 为进度指针，是唯一在线持久化更新的状态。冻结策略仅条件于当前子目标 

  A_t ∼ π_θ(o_t, g_{p_t})

- 用物理证据验证“当前子目标是否真正完成”，只有验证通过才推进指针，从而实现 **执行 → 验证 → 进度** 的闭环。

### 2.2 事件触发验证：何时验证

- 利用**夹爪载荷状态机**（基于夹爪开度宽度 w_t 的迟滞 FSM）检测交互事件：

  e_t ∈ {∅, G+, R+, R0}

  其中 G+ 表示稳定负重抓取，R+ 表示负重释放，R0 表示空手释放。
- **兼容性函数 χ**：仅当事件类型与当前子目标类型匹配时才触发验证（G+ 只验证 grasp 子目标，R+ 只验证 placement 子目标）；空释放及其他不匹配组合直接丢弃。
- 设计原则：**交互事件只定位“何时应检查结果”，本身不等于成就证据**。

### 2.3 抓取成功验证：相干运动点跟踪

- **物理直觉**：成功抓取表现为物体随夹爪一起上升，是运动学问题。
- **实现**：
  - 抓取瞬间记录末端执行器位置，投影到前视相机成像平面，在投影点周围采样规则 6×6 网格，共 36 个查询点；
  - 用冻结的 **CoTracker3** 跟踪随后 L 帧的上升运动裁剪片段，得到点轨迹与可见度分数；
  - 由可见度过滤（η_vis = 0.5）、取最大上升位移的前 1/3 轨迹、再取中位数，得到响应 r^G；
  - 若 r^G ≥ δ_G（4 px），判定抓取成功。
- 这种设计抑制静态背景轨迹和孤立跟踪误差，度量的是**物体真实运动**而非夹爪指令运动。

### 2.4 放置成功验证：语言条件跨视角比较

- **物理直觉**：放置成功需确认“被操作物体与目标区域是否建立了任务要求的语义关系”，属于语义问题。
- **实现**：
  - 在释放事件前后，从**前视相机与腕部相机**各采集 K 帧时间聚合观测（post-release 窗口在释放后经 30~40 帧沉降延迟采样）；
  - 冻结的 **SigLIP** 编码器提取前后帧视觉嵌入与子目标文本嵌入；
  - 特征向量由前视前后差、腕部前后观、本体感觉窗口及语言查询拼接而成；
  - 2.43M 参数的轻量 MLP 预测放置成功概率。
- 可恢复的平面放置用严格阈值（0.5），不可恢复的容器放置用过宽松阈值（0.05），以规避“假拒绝导致多塞一个物体破坏计数”的风险。

### 2.5 指针转移规则

- 验证结果驱动三态转移（设定回退子目标函数 B(p)、可逆标志 ζ）：

  p⁺ = min(p⁻+1, T)（验证成功-前进）；B(p⁻)（失败且可恢复-回滚到对应抓取子目标）；p⁻（其他-保持）
- 附带安全机制：连续拒绝上限（可恢复放置 2 次、不可逆放置 3 次、抓取 3 次）、卡死超时、终端前放置复核等，防止验证器假阴性造成死锁或计数错误。

## 6. 主要结论与发现

1. **尝试型记忆会导致严重性能塌陷**：同一子目标策略下，每次操作尝试都推进指针的“无验证写入”在 PickXTimes 上只有 32.0%，远低于无进度记忆的 36.0%，远低于 AGM 的 100.0%——证明未经验证的写入比没有记忆更有害。
2. **成就锚定写入带来决定性提升**：AGM 在 PickXTimes 达 100.0%、BinFill 达 84.0%，四任务平均 55.96%，超过最强记忆增强基线 MemER（48.83%）7.1 个百分点，几乎翻倍于冻结基座策略（28.78%）。
3. **任务进度是瓶颈而非技能水平**：π0.5 在 N=1 近乎满分（100/90），N=5 时降到 0；AGM 使 PickXTimes 全程保持 100%，证明策略本身具备能力，缺的只是任务状态。
4. **纪律性写入 > 记忆容量**：AGM 只加 231M 冻结参数 + 2.43M 可训练参数，远小于 SimpleSG/MemER 的 4B LoRA 外部 VLM，效果反而更好；结论是可靠记忆更多取决于“何时有资格写入”而非容量。
5. **框架跨骨干、跨平台泛化**：即使 π0 本身几乎不可用，同一套规则与阈值不加调整也能显著提升其表现；实体机器人上 PickXTimes 达 100%、BinFill 大 N 达 60-80%，收益非仿真假象。

## 7. 方法亮点

- **问题切分清晰**：因果链完整——“谁负责定位潜在状态变化”（夹爪状态机）、“谁负责判定是否发生”（冻结感知模型）、“谁负责更新状态”（轻量验证头），三者解耦。
- **区分事件与成就**：明确“尝试≠完成”，这是对机器人记忆文献中普遍把动作流直接当任务状态做法的重要纠偏。
- **借用而非训练基础模型能力**：CoTracker3 负责运动学判定（无需训练），SigLIP 负责语义跨模态判定，只训练单个 2.43M 头，知识利用效率高，避免了大模型在测试时被反复调用。
- **可恢复性感知的状态转移**：丢弃/回滚/严格性与放置的可逆性挂钩，配合不可逆场景的宽松接受阈值与死锁护栏，算法在“假接受”与“假拒绝”两种风险间做了合理权衡。
- **实验控制思维严谨**：通过“AGM / attempt-based / whole instruction”三者同接口对照，精确定位增益来自“verified writing”而非子目标分解本身；实体实验也验证了这一机制。

## 8. 不足与局限

- **验证词汇局限于抓取类事件**：AGM 只能对“夹爪开/合界定”的子目标生效；推、滑、铰接物体操作、持续抓握下的工具使用等因事件兼容性缺失，会落入原始冻结策略，不产生改进。这解释了 SwingXTimes 与 StopCube 无提升。
- **任务模型是线性序列而非一般图结构**：无法表达分支计划、部分有序子目标或跨重复的回滚；回滚只能回到当前循环的对应抓取子目标。可恢复性在指令展开时静态决定，未能适应场景意外变化。
- **上限拒绝机制是双刃剑**：死锁护栏靠“未验证推进指针”打破 liveness，可能把活性失败转化为进度错误——论文诚实承认 AGM 只能保证未验证写入“罕见且有界”，而非“零发生”。
- **验证器误差直接限制性能上限**：假接受写入错误进度，假拒绝浪费时间；论文的阈值不对称只是管理这种权衡而非消除它。
- **统计报告不完整**：主结果部分取两次平均、消融为单次运行，未报告方差/置信区间或多次独立重复的完整分布，较难判断差异的统计显著性。
