## 摘要
现代端到端驾驶智能体能够实现较高的平均性能，但仍然会违反人类驾驶员绝不会忽略的基本交通规则。这源于结构性问题：它们学习的是统计模式，而非保障安全驾驶的物理条件，导致其决策过程不透明，安全约束得不到执行。我们提出一种神经符号安全守卫，这是一种轻量级模块，附加在已训练智能体的最终命令接口上。在命令到达车辆之前，它会根据显式安全规则检查该命令，并仅在必要时用最近的安全替代命令替换它。每次干预都直接可执行，并且可追溯到触发它的规则，而守卫本身无需重新训练，也不增加任何学习组件。在长尾基准Fail2Drive和Bench2Drive上，以最先进的TransFuser v6（TFv6）作为案例研究进行评估，守卫将成功率提升了15%，并将安全关键碰撞减少了高达53%，同时保持了原有的驾驶得分。

## Abstract
Modern end-to-end driving agents can achieve high average performance yet still violate basic traffic rules that a human driver would never miss. The reason is structural: they learn statistical patterns rather than the physical conditions that guarantee safe driving, leaving their decision-making process opaque and safety constraints unenforced. We introduce a neuro-symbolic safety guard, a lightweight module that attaches to the final command interface of an already-trained agent. Immediately before a command reaches the vehicle, it checks the command against explicit safety rules and, only when necessary, replaces it with the nearest safe alternative. Each intervention is directly executable and traceable to the rule that triggered it, while the guard itself requires no retraining and adds no learned component. Evaluated on the long-tail benchmarks Fail2Drive and Bench2Drive using the state-of-the-art TransFuser v6 (TFv6) as a case study, the guard improves Success Rate by 15% and reduces safety-critical collisions by up to 53%, while preserving the original Driving Score.

- **核心问题**：现代端到端自动驾驶智能体虽然平均benchmark成绩优异，但依然会犯人类驾驶员绝不会犯的、显而易见的基本安全错误——如闯红灯、跟车制动过晚、不安全通过人行横道等。
- **根本原因**：这类模型在结构上学习的是**统计数据中的相关性模式**，而非保障安全的**物理条件**（如制动距离、碰撞几何、速度边界），导致其决策过程不透明，安全约束从未被显式执行。熟悉路线的胜任力无法迁移到罕见场景（long-tail）。
- **现实代价**：以2023年Cruise机器人出租车拖拽行人事件为例，单次罕见的不安全交互足以让整个部署项目停滞，凸显安全性长尾问题的现实紧迫性。
- **整体含义**：论文主张，学习模型提供“灵活性”，符号规则提供“保证”，二者互补；判断自动驾驶智能体不应只看“跑了多远”，而要看其命令被**保证满足的安全条件**。

## 2. 方法论：神经符号安全守卫（Neuro-Symbolic Safety Guard）

### 2.1 核心思想
- 在**已训练冻结的端到端驾驶模型**与车辆最终执行接口之间，插入一个轻量级安全守卫模块。
- 守卫读取模型自身已暴露的场景信号，用显式规则判定拟执行的命令是否安全；仅当不安全时，将命令替换为**最近的安全备选**；安全时完全不动。
- 无需重新训练、不增加任何学习组件，可附加到任何暴露场景信号的端到端模型。

### 2.2 输入与控制空间
- 控制向量：$x = [u, s]^\top$，其中 $u = \tau - \beta$ 为有符号纵向命令（油门减制动），$s$ 为转向命令。
- 场景状态：$S(o) = (K, B, V, W)$，即检测框（CenterNet格式）、BEV语义图、雷达点迹、模型自生的规划路径点（waypoints）。
- 名义提议：$x_0 = \pi_\theta(o)$，即冻结策略的输出。

### 2.3 五条安全规则（全部以闭式推导，每条等价于一个控制量界限）
| 规则 | 名称 | 约束轴 | 功能 |
|---|---|---|---|
| R1 | Planned-Path Collision Safeguard | u | 沿规划路径检测障碍物，以RSS安全距离公式求最大允许速度 |
| R2 | Speed-Limit Compliance | u | 限制城市道路超速 |
| R3 | Red-Light Stop Compliance | u | 红灯时强制减速停止，按置信度加权 |
| R4 | Pedestrian Right-of-Way Protection | u | 行人及过街走廊的避让制动 |
| R5 | Speed-Conditioned Steering Stability | s | 基于自行车模型，高速下收紧转向角上限 |

- R1 的四个步骤：构建路径折线 → 以路径走廊门控（仅关心路径上的障碍物，避免误刹）→ 双通道感知（分类感知的相机通道 + 类别无关的雷达通道融合，能捕获训练集外物体如动物、杂物）→ 按RSS制动余量计算 `g_coll`。
- R2–R5 共用统一模板：$v_{stop} = \sqrt{2 a_{brake} d}$，再由当前速度对比产生纵向控制界限 $g_\bullet(o) = \text{clip}((v_{stop} - v_{ref}) / v_{comfort}, u_{min}, u_{max})$。

### 2.4 安全守卫的“读-推理-约束”三段流程
- **读**：从单次前向传播中提取场景状态 $S(o)$。
- **推理**：规则集将场景映射为界向量 $g(o) = (g_{coll}, g_{speed}, g_{red}, g_{ped}, g_{lat})^\top$。
- **约束**：求解约束集 $C(o) = \{x \in U : Dx \le g(o)\}$ 上的欧氏投影（二次规划）：
  $x^\ast = \arg\min_{x \in C(o)} \frac{1}{2} \|x - x_0\|_2^2$。
- 多个规则同时过约束时，最紧的界生效，冲突偏向安全。
- 可信任性依据：保持良好驾驶（仅在必要时最小改动）、安全性构造保证（所有纵向界限都是制动可到速度）、审计可追溯（确定性规则，每次干预可定位到触发规则）。

## 3. 实验设计

- **主基准**：Fail2Drive（基于CARLA v2，Town13，200条短路线，平均长219米，覆盖17类罕见场景）。路线由100对匹配场景构成：
  - *分布内（In-Distribution）*：用训练中熟悉的目标外观和布局复现危险场景；
  - *泛化（Generalization）*：同一任务、同一道路，仅改变场景物体外观与布局，检验模型是否“死记硬背”。
- **次要基准**：Bench2Drive（作为能力保持性检验）。
- **被对比方法（Fail2Drive公开榜）**：AlignDrive (2026)、TF++ (2023)、TFv6 (2026)、BevAD (2026)、BridgeDrive (2026)，以及特权专家代理 PlanT 2.0 与 PDM-Lite-F2D（作为参考上限，非竞争者）。
- **核心对比**：同一冻结 TFv6 权重，加守卫（TFv6 + NS）与不加守卫（TFv6）的配对对比，确保差异完全归因于守卫。
- **指标**：Driving Score (DS)、Success Rate (SR)、二者的调和平均 HM 为主要判据；另做逐违章（per-infraction）分析。
- **设置**：CARLA 0.9.15（Leaderboard 2.0），按 Fail2Drive 固定协议运行，三个种子遍历每条路线，仅推理，不训练微调。

## 6. 主要结论与发现

- **泛化split（关键安全场景）**：守卫使成功率提升 10.6 个百分点（相对 +15.0%），HM提升 5.8 个百分点（+7.8%），驾驶得分不降反微升（+0.6%）。
- **安全关键碰撞减少**：行人碰撞 6.3%→3.0%，布局碰撞 15.0%→7.7%，车辆碰撞 4.7%→3.3%，**最高减少53%**。
- **泛化损失最小**：TFv6 单独损失 18.4% HM，加守卫后降至 9.8%，是所有学习型代理中最小，仅次于读取真值的特权专家 PDM-Lite-F2D（1.8%）。
- **代价**：分布内 split 损失 2.5% HM（DS −3.9%、SR −1.1%）；守卫只能减速，代价体现为 min-speed 违规增多（72.3%→92.0%）和超时增加。
- **方法论的启示**：同一干预在DS下只表现为+0.6%，在SR下为+15.0%，说明现有指标把“谨慎停车”与“碰撞”混为一谈；论文呼吁长尾基准应将二者视为类别不同的结果。

## 7. 优点

- **方法亮点**：
  - 即插即用：不改动模型权重，适用于任何暴露场景信号的端到端模型；
  - 每条规则可追溯、可审计：干预必然可归因到具体物理规则，无黑箱；
  - 规则从成熟模型（RSS安全距离、自行车运动学）闭式推导，非调参启发式；
  - 路径相对而非框相对的门控设计，避免误刹，同时用雷达的类别无关通道覆盖训练集外的异常物体（如动物）；
  - 欧氏投影保证“最小干预”——安全时零干预，不安全时尽量少改命令。
- **实验亮点**：
  - 成对同权重对比，对守卫的归因干净；
  - 采用分布内→泛化的配对split，直接量化“死记硬背”的程度；
  - 明确报告代价（分布内下降、减速增加），不对trade-off遮遮掩掩；
  - 用调和平均作为主指标，避免单一指标被刷。

## 8. 不足与局限

- **实验层面**：
  - 只在模拟器中验证（CARLA），无真实平台验证，实际感知噪声、执行延迟、通信丢包等影响未知；
  - 完整定量实验仅基于 TFv6 一个骨干，广义普适性证据不足；
  - GPU算力、推理时延、内存开销等工程指标未报告，难以评估部署成本。
- **方法层面**：
  - 守卫的**安全保证依赖感知正确性**：若检测/雷达漏报，规则无从触发（论文也承认这一点是“可量化上限”）；
  - 守卫只能“阻止”不安全命令，**不能发明安全的替代轨迹**——当规划器本身规划错误（如借对象逆行）时，只能停车等超时，无法主动脱困；
  - 规则覆盖面有限：仅五条规则（碰撞、超速、红灯、行人、转向稳定性），不涵盖所有危险类型；
  - 分布内性能（2.5% HM）的下降表明保守边界仍有过度干预，安全裕度与通行效率之间的折衷需要进一步调优；
  - 对信号暴露的依赖：模型若不主动输出路径点、BEV等中间信号，需附加额外头，可能在部分架构上增加适配成本。
- **结果层面**：真实驾驶中的长尾场景远不能由200条模拟路线完全代表。
