## 摘要
视觉-语言-动作（VLA）模型能够将场景理解、语义推理和轨迹生成连接起来，用于自动驾驶。然而，冗长的自然语言思维链（CoT）并不适合实时控制，因为它是开放式的、解码成本高，并且难以作为面向动作的表示进行优化。我们提出了XCoT-VLA，它将描述性理由替换为从自动构建的“原因-动作”监督中学习到的紧凑可执行CoT标记。记录轨迹提供动作证据，场景上下文提供因果语义。预测的XCoT序列保持在上下文中，并通过共享的多模态自注意力来调节固定的轨迹查询。确定性的标记-功能路由将Reason FFN应用于XCoT标记，将Control FFN应用于轨迹查询，以进行流匹配轨迹生成。我们进一步引入了XCoT策略优化（XCPO），作为同一可执行标记空间中的可选优化扩展。在通用分布集上，XCoT-VLA将纵向ADE从1.645降至1.323，在变道场景中，横向FDE从1.616降至0.648。通过仅用2-6个可执行XCoT标记来表示面向驾驶的推理，我们的方法显著减少了自回归推理开销，并保持在实时规划预算内。这些结果表明，面向驾驶的推理可以紧凑、可执行，并直接与轨迹生成相连。

## Abstract
Vision-Language-Action (VLA) models can connect scene understanding, semantic reasoning, and trajectory generation for autonomous driving. However, verbose natural-language Chain-of-Thought (CoT) is poorly suited to real-time control because it is open-ended, costly to decode, and difficult to optimize as an action-facing representation. We propose XCoT-VLA, which replaces descriptive rationales with compact executable CoT tokens learned from automatically constructed Reason-Action supervision. Logged trajectories provide action evidence, while scene context supplies causal semantics. The predicted XCoT sequence remains in context and conditions fixed trajectory queries through shared multimodal self-attention. Deterministic token-function routing applies the Reason FFN to XCoT tokens and the Control FFN to trajectory queries for flow-matching trajectory generation. We further introduce XCoT Policy Optimization (XCPO) as an optional refinement extension in the same executable token space. XCoT-VLA reduces longitudinal ADE from 1.645 to 1.323 on a general-distribution set and lateral FDE from 1.616 to 0.648 in lane-change scenarios. By representing driving-oriented reasoning with only 2-6 executable XCoT tokens, our method substantially reduces autoregressive reasoning overhead and remains within the real-time planning budget. These results demonstrate that driving-oriented reasoning can be compact, executable, and directly connected to trajectory generation.

## 2. 论文提出的方法论

### 2.1 核心思想

- 将驾驶推理表示为一小段离散的“可执行语义动作 token”序列，例如 `LEFT_TURN_PREPARE`、`DECELERATE`、`RED_LIGHT_HOLD`、`NAV_LEFT_LANE_CHANGE` 等。
- 这些 token 不是最终的低层动作，而是介于多模态推理与连续控制之间的“语义-动作接口”。
- 整体监督链为：  
  **记录轨迹 + 场景上下文 → Reason–Action 监督 → 可执行 XCoT token 序列 → 轨迹解码**。

### 2.2 XCoT 训练数据构造管线

- 对每个日志样本 `(o_t, τ_t)`，通过三步构造标签：
  1. **动作证据提取**：从 -3s~6s 的日志轨迹提取纵向和横向行为，如速度保持、减速、车道保持、变道等；
  2. **语义接地**：结合场景上下文（导航意图、交通规则、道路结构、周围交互、安全约束）推理出候选原因，并通过一致性打分选择最合适的因果语义；
  3. **语义压缩**：通过固定、可解释的 taxonomy 将 Reason–Action 对压缩为 2–6 个 XCoT token，并加上 EOS。
- 使用“多个视觉语言专家 + 规则模板 + 关键词 + embedding 相似度”来对齐候选原因；语言仅作为离线监督来源，不直接用于推理生成。

### 2.3 解耦的推理-控制架构

- 模型包含共享多模态自注意力层，以及两个独立的 FFN 分支：
  - **Reason FFN**：处理所有非轨迹 token（视觉、文本、任务提示、自车状态、导航指令、XCoT token）；
  - **Control FFN**：仅处理 24 个固定轨迹查询。
- 确定性 token-功能路由：不学习路由器，而是根据 token 类型固定分配 FFN。
- 轨迹查询通过共享自注意力可以“看到”XCoT 和观测上下文，但 FFN 更新只来自 Control FFN。
- 轨迹生成采用 **Conditional Flow Matching（CFM）**：从高斯噪声插值到专家运动序列，学习速度网络；预测输出为 24 步的纵向加速度和横摆角变化，再通过时间积分得到 ego 坐标轨迹。

### 2.4 两阶段训练

- **Stage I（SFT）**：
  - XCoT 预测采用交叉熵损失（teacher forcing）；
  - 轨迹生成采用 flow-matching 损失；
  - 总损失为 `L = λ_XCoT * L_XCoT + λ_FM * L_FM`。
- **Stage II（XCPO，可选）**：
  - 冻结执行栈（视觉编码器、共享注意力、Control FFN、flow-matching 轨迹头）；
  - 只更新 Reason FFN 和 XCoT 预测头；
  - 在可执行 XCoT token 空间中进行 group-relative policy optimization，使用 clipped 序列级目标 + KL 散度约束到 Stage-I 参考策略；
  - 奖励来自 rollout 轨迹的加权评分，并在组内做相对 advantage 归一化。

## 6. 论文的主要结论与发现

- XCoT-VLA 在开放环路轨迹规划上显著优于无推理和自然语言 CoT 基线：
  - 通用集：纵向 ADE-6s 从 1.6452 降至 1.3233，纵向 FDE-6s 从 4.3541 降至 3.0887；
  - 换道集：横向 ADE-6s 从 0.5941 降至 0.3091，横向 FDE-6s 从 1.6160 降至 0.6484。
- 可执行推理在“导航条件化的横向决策”上收益最大；自然语言 CoT 在横向精度上不一致，潜在 token 有帮助但仍不如完整 Reason–Action 监督。
- 2–6 个 XCoT token 的推理接口在 H100 上最坏情况延迟保持在 12 Hz 预算内，而 40–80 token 的自然语言 CoT 在所有输入长度下都超预算。
- 解耦 Reason/Control FFN 的微调比联合微调更稳定，能显著改善横向精度，同时保持短时纵向精度。
- 定性结果展示 XCoT-VLA 更“主动”：更早换道、提前为红灯减速、在效率换道中自适应加速。

## 7. 优点

- **推理接口设计有创新性**：用可执行语义 token 建立“推理-动作”界面，兼顾可解释性和实时性，不是简单压缩语言，也不是直接输出动作。
- **数据构建流程完整**：从日志轨迹提取动作证据，用场景上下文做因果接地，再用固定 taxonomy 压缩成规范 token，自动生成大规模监督。
- **架构设计解耦**：共享注意力 + Reason/Control 双 FFN 的确定性路由，使推理 token 能影响轨迹生成，又避免了联合微调的不稳定。
- **延迟意识强**：将推理开销明确纳入实时规划预算评估，具有很强的工程落地导向。
- **策略优化扩展**：XCPO 在可解释、可执行的 token 空间里做强化学习，而非直接优化黑盒连续动作或自由文本，为后续闭环优化提供接口。
- 实验表格和指标表述清晰，区分纵向/横向 ADE/FDE，比单一欧氏距离更有诊断性。

## 8. 不足与局限

- **缺少闭环验证**：开放环路 ADE/FDE 不能完全反映真实自动驾驶中的安全性、舒适性和交互质量。
- **XCPO 未评估**：作为 Stage II 的强化学习扩展，论文只给出方法，没有定量结果，降低了本文的完整度。
- **交互协商能力有限**：作者承认 XCoT 对周围车辆的交互性协商建模不足。
- **感知错误敏感**：若交通规则感知（如红绿灯）出错，推理 token 和轨迹都可能被误导。
- **纵向舒适性提升较小**：实验显示主要收益集中在横向/换道，纵向长时误差仍相对薄弱。
- **自动标注可能存在噪声**：Reason–Action 标签依赖规则模板和视觉语言专家的一致性筛选，复杂场景可能仍有歧义；人工标注只占 200k，覆盖面有限。
- **外部对比不足**：没有与其他公开发布的方法或数据集基准（如 nuScenes、OpenDriveVLA 等）做横向比较，难以判断相对整体 SOTA 的水平。
