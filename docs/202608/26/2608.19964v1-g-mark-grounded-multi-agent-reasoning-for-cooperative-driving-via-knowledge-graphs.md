## 摘要
自动驾驶系统必须在部分可观测性下运行，其中安全关键对象可能被遮挡，或者仅对邻近的网联车辆可见。车对车协作可以减少这种不确定性，但现有的协作驾驶方法通常将多智能体证据压缩为潜在特征或隐藏的多模态状态。因此，它们模糊了哪个智能体观察到每个对象、该对象对自车是否可见，以及冲突证据如何影响下游决策。我们提出G-MARK，一种基于知识图谱的接地多智能体推理框架，将协作的以对象为中心的观测转换为显式的、具有来源感知的知识图谱（KGs）。生成的KGs保留对象假设及其来源归属、自车与伙伴可见性、不确定性、冲突、空间关系和规划相关上下文。然后，G-MARK从这些KGs中推导出共享特征表示，使轻量级任务头能够支持对象推理、运动预测、控制选择和轨迹预测。与最先进的基线相比，G-MARK将遮挡推理准确性提高了42.2%，控制选择误差降低了13.1%，并以25.6倍更小的结构化通信负载实现了相当的轨迹规划准确性。我们的代码可在 https://github.com/bhavyagupta98/g-mark 获取。

## Abstract
Autonomous driving systems must operate under partial observability, where safety-critical objects may be occluded or visible only to neighboring connected vehicles. Vehicle-to-vehicle cooperation can reduce this uncertainty, but existing cooperative driving methods often compress multi-agent evidence into latent features or hidden multimodal states. As a result, they obscure which agent observed each object, whether the object is visible to the ego vehicle, and how conflicting evidence affects downstream decisions. We propose G-MARK, a grounded multi-agent reasoning framework that converts cooperative object-centric observations into explicit provenance-aware knowledge graphs (KGs). The resulting KGs preserve object hypotheses together with their source attribution, ego-versus-partner visibility, uncertainty, conflicts, spatial relations, and planning-relevant context. G-MARK then derives a shared feature representation from these KGs, enabling lightweight task heads to support object reasoning, motion prediction, control selection, and trajectory forecasting. Compared with the state-of-the-art baseline, GMARK improves occlusion reasoning accuracy by 42.2%, reduces control-selection error by 13.1%, and achieves comparable trajectory-planning accuracy with a 25.6x smaller structured communication payload. Our code is available at https://github.com/bhavyagupta98/g-mark.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式与算法流程

### 2.1 核心思想

- **中心设计原则**：**"延迟不可逆融合直到下游推理任务被确定"**（task-conditioned delayed evidence fusion）。不将多智能体观测直接压缩为单一融合结果，而是先构建provenance-aware的协作知识图谱，保留完整的证据结构，再由不同任务头按需查询。
- **核心创新**：将协作场景表示为由**智能体节点（agent nodes）**、**观测节点（observation nodes）**和**目标假设节点（object-hypothesis nodes）**三类实体组成的知识图谱，通过有类型的关系边（typed relations）连接，显式存储来源、支持关系、空间关系、规划上下文和证据一致性。

### 2.2 四阶段算法流程

**阶段一：协作KG生成（Cooperative KG Generation）**

- 每个CAV的处理后感知输出被实例化为本地证据KG，包含：
  - **智能体节点** `vAt,i`：存储身份、位姿、时间戳、ege/partner角色；
  - **观测节点** `vOt,i,j`：表示单个本地目标观测 `o(i)t,j`；
  - **目标假设节点** `vHt`：表示共享目标候选或通信得到的对象候选。
- 每条观测表示为：
  ```
  o(i)t,j = ( x(i)t,j, τ(i)t,j, c(i)t,j, ai, t, η(i)t,j )
  ```
  其中 `x` 为位置/边界框、`τ` 为语义类型、`c` 为检测置信度、`ai` 为来源智能体、`η` 为附加属性（速度、轨迹ID等）。
- 图谱形式：`Gt = (Vt, Et)`，其中 `Vt = VAt ∪ VOt ∪ VHt`。
- 有类型关系包括：source（智能体→观测）、support（观测→假设）、spatial（self/behind/left-of/right-of/near）、planning-context（near-trajectory/path-relevant）、evidence-consistency（cooperatively-supported/low-conflict）。

**阶段二：保守关联（Conservative Association）**

- 使用确定性门控规则决定哪些观察可以被关联。门控函数为：
  ```
  δt(vOp, vOq) = 1[ type_match(τp, τq) ∧ d(xp, xq) < ε(τp,τq) ]
  ```
  其中 `d(·)` 为距离，`ε` 为类别相关的关联阈值，要求语义类别完全一致（保守设计，避免跨类合并）。
- 亲和度分数：
  ```
  αt,pq = 1 − d(xp, xq)/ε(τp,τq)  (若δ=1)；否则 0
  ```
- 融合位置 `xh` 为支持观测位置的置信度加权平均。
- 置信度聚合采用**有界noisy-or聚合**：
  ```
  ch = 1 − Π_{vO∈S(h)} (1 − c(vO))
  ```
- **关键设计**：不匹配的观测被保留为**弱候选假设**（candidate hypothesis），而非丢弃——这是安全导向的选择，使伙伴独有观测仍可用于下游推理。

**阶段三：协作上下文增强（Cooperative Context Enrichment）**

- 每个假设 `h` 被增强为富化向量 `φ(h)`，包含五个维度（对应表II）：
  - `φprov(h)`：来源与支持（source agents、support counts、ego/partner/cooperative状态）；
  - `φvis(h)`：自车相对和智能体相对可见性（visible/occluded/uncertain）；
  - `φunc(h)`：不确定性（弱置信度、候选状态、有限支持）；
  - `φdis(h)`：跨智能体不一致性（几何/语义冲突）；
  - `φplan(h)`：规划相关性（轨迹邻近度、运动线索、控制上下文）。
- 最终KG特征向量 `ψ(h)` 拼接对象状态属性（位置、类型、置信度、运动线索）与富化向量 `φ(h)`，供下游任务直接查询。

**阶段四：统一KG任务头（Unified KG Task Heads）**

- 任务推理形式为：`yk = Rk( Gt, {ψ(h): h ∈ VHt} )`，其中 `Rk` 为任务头，可以是确定性检索/排序函数或轻量级学习预测器。

- **保守关联保留弱证据**：不丢弃未匹配观测，而是作为候选假设保留，是安全导向的合理设计。
- **轻量级、通信高效**：不依赖大规模多模态模型，仅使用轻量级回归/分类头即可达到甚至超越VLM基线，同时通信负载大幅降低。
