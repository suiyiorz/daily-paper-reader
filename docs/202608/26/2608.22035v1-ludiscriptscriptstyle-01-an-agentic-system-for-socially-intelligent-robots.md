## 摘要
机器人基础模型极大地推进了感知与控制，但自然的人机协作需要的不仅仅是执行孤立的指令。机器人必须识别歧义，在轮次之间保持上下文，传达其意图，并在用户的意图变化时调整正在执行的行为。我们提出了Ludi_{0.1}，一个面向社会智能机器人的智能体系统，它集成了交互式语音、多模态推理、记忆、导航和学习到的操作能力。其决策核心是一个经过微调的视觉语言模型，训练数据包含多轮交互轨迹，涵盖了模糊请求、澄清、更正、打断、社交与任务对话的混合以及多步骤任务。一个专门设计的框架管理模型与工具交互的循环，而专门的导航和操作策略则执行物理技能。Ludi_{0.1}展示了当前实现流畅人机协作的实用路径，同时生成了开发更深度集成的人机基础模型所需的多模态交互轨迹。

## Abstract
Robot foundation models have substantially advanced perception and control, but natural human-robot collaboration requires more than executing isolated commands. A robot must recognize ambiguity, maintain context across turns, communicate its intentions, and revise ongoing behavior as the user's intent changes. We present $\scriptstyle\mathsf{Ludi}_{\scriptscriptstyle 0.1}$, an agentic system for socially intelligent robots that integrates interactive speech, multimodal reasoning, memory, navigation, and learned manipulation. Its decision-making core is a fine-tuned vision-language model trained on multi-turn interaction traces spanning ambiguous requests, clarifications, corrections, interruptions, mixed social and task dialogue, and multi-step tasks. A purpose-built harness manages the model-tool interaction loop, while specialized navigation and manipulation policies execute physical skills. Ludi${}_{\scriptscriptstyle 0.1}$ demonstrates a practical path toward fluid human-robot collaboration today while producing the multimodal interaction traces needed to develop a more deeply integrated foundation model for robots and people.

## 1. 核心问题与整体含义（动机与背景）

- **研究背景**：机器人基础模型（如基于 LLM/VLM 的感知与控制系统）在物理任务执行和泛化能力上取得了显著进展，但自然的人机协作远不止于执行孤立指令。
- **核心问题**：机器人必须能够——识别歧义、跨轮次维持上下文、传达自身意图，并在用户意图中途改变时（例如纠正、打断）实时调整正在执行的行为。这是一种对人们而言很自然、但对机器人极具挑战的"社会智能"。
- **示例场景**：用户让 Unitree G1 人形机器人"给 Chloe 带一罐可乐"，机器人已伸手去拿红色可乐罐时，用户突然改口"她其实更喜欢百事"。机器人需要理解该更正覆盖先前选择，放弃已开始的动作，改拿百事，导航至卧室并送达。
- **整体含义**：该问题要求语音、感知、记忆、推理、导航和操作作为一个集成系统协同运作，使新信息能够重塑正在进行的物理行为。论文主张：当前无需等待单一端到端基础模型，即可通过智能体架构实现流畅的人机协作，同时积累高质量多模态交互数据，为未来更深度集成的"人机基础模型"铺路。

## 2. 提出的方法论

### 2.1 总体架构：智能体范式而非端到端模型

- 刻意选择**智能体架构**：由中央 VLM 做决策，专用 harness 管理交互循环，专门化策略执行物理技能。
- 核心在于将"执行层模块化"与"交互层集成"相结合。

### 2.2 决策核心：微调视觉语言模型（VLM）

- 基础模型：**Qwen3.5** 视觉语言模型，规模为 4B 和 9B，使用 **LoRA** 进行监督微调。
- 输入：机器人第一人称（ego）图像、头戴 360° 相机全景上下文、转录的用户语音、交互历史（含自身推理）及先前工具调用结果。
- 输出：从固定小型工具集中选择一个动作。
- 微调数据：**14,432 条完全合成的多轮交互轨迹**，由组合式场景生成器构建，覆盖歧义请求、任务中途更正、打断、多步差事、社交与任务混合对话等。每条轨迹由状态机与策略表保证工具调用正确性，教师 LLM 撰写语言（推理文本、回应、用户话语），再经过规则检查与两阶段 LLM 评判的质量门，失败可修订两次，仍失败则丢弃。

### 2.3 工具集（Agent Interface）

| 工具 | 功能 |
|---|---|
| `say` | 对用户说话（回应、提问澄清） |
| `lookup_keypoints` | 查询静态地图中按距离排序的命名位置 |
| `navigate` | 移动到指定命名位置 |
| `reachability` | 检查可见物体是否可抓取及用哪只手臂 |
| `vla` | 调用 VLA 策略执行抓取/放置等操作 |
| `wait` | 保持观察等待变化 |

- 工具以类型化函数调用 schema 暴露，运行时动态填充（如物体类型从 VLA 注册表读取，新增技能无需重训 agent）。harness 强制契约：每轮至多一个动作性工具调用、pick 前必须有成功的 reachability 检查。

### 2.4 Harness 工程（实时交互保障）

- **非阻塞上下文压缩**：辅助模型在后台压缩老上下文，仅在轮次间隙安装，不打断运行中的 agent 循环。
- **视觉预填充与异步语音**：后台持续刷新相机输入并预填充视觉特征，降低响应延迟；语音输出走 FIFO 音频队列，推理与动作不阻塞。
- **本地语音管线**：sherpa-onnx 四线程配置，10 秒英语语音转录平均 94.7ms、P95 99.2ms，无转录错误；新语音输入可随时重定向正在进行的导航/操作。

### 2.5 导航与人形移动

- 定位：KISS-ICP LiDAR 里程计 + 扩展卡尔曼滤波（EKF），超参数由 Optuna 自动调优。
- 高层导航：VLM 基于命名关键点（房间、桌子等）导航，不直接推理度量坐标。
- 连续规划：针对 G1 的朝向感知连续规划器，五次样条轨迹，朝向与行进方向独立规划，使用多圆足迹处理转向、横移、倒退和窄通道，支持平滑重规划。

### 2.6 专用 VLA 操作策略

- 基于 **GR00T N1.7**，以其预训练的 Unitree G1 具身组件初始化。
- 仅控制手臂与夹爪自由度（不含全身运动）；预测 30 步动作块（30Hz 下约 1 秒），同步执行。
- 通过真实 G1 遥操作采集数据，在实际家庭拾放场景中微调。
- 仿真筛选：高保真 Isaac Sim 中校准相机位姿、场景几何、电机动力学（相机掩膜 IoU≈0.92；Dex-3 手追踪误差 0.132→0.043 rad，指尖误差≤13mm；动力学泛化到 17 个留出片段），但最终仍以真机验证为准。

## 3. 实验设计

- **主基准：Interaction Core28**——AI2-THOR + ProcTHOR 生成的多样 3D 家庭环境中的闭环端到端基准，共 **28 个场景**，覆盖：递送、感知与报告、需澄清的歧义、搜索失败与不可达物体的鲁棒性、任务中途交互。
- **评测方式**：每个场景定义金标准工具调用轨迹；评分同时考察交互过程（确定性交互门，如"歧义时先澄清再行动"）和模拟器最终状态。仅当失败仅涉及口语语义门时，才允许 LLM 评判员翻案；涉及工具使用、任务执行或最终状态的失败不可翻案。
- **对比方法**：GPT-5.6（GEPA 优化提示）、Qwen3.5-4B（原版/微调）、Qwen3.5-9B（原版/微调）。
- **结果**：微调后成功率约翻倍；微调 9B 达 20/28，接近 GPT-5.6 的 26/28；剩余失败集中于任务递送端的空间接地（物体选对、计划对，但交接点定位不精确）。
- **其他实验**：语音延迟基准（STT 延迟）；Isaac Sim 标定误差测量；真实机器人端到端演示（图 1 所示中途更改意图场景）；VLA 策略真机拾放验证。

## 6. 主要结论与发现

1. **智能体架构可行**：将微调 VLM 作为推理核心，配合 harness 和专门工具，即可在现有人形机器人上实现包含澄清、纠错、中断处理的持续人机交互。
2. **微调显著有效**：针对多轮交互轨迹的监督微调使 Core28 成功率较原版模型约翻倍（4B：10→17；9B：11→20），逼近带优化提示的前沿模型 GPT-5.6（26/28）。
3. **主要瓶颈明确**：当前失败集中在任务末端交接点的空间接地精度，而非规划或物体选择。
4. **工程化实时交互可行**：本地 STT 延迟约 95ms、异步语音与非阻塞上下文压缩能够支撑流畅交互。
5. **数据积累价值**：该系统同时是"可工作的具身智能体"和"数据生成测试床"，为未来 Ludi 1.0 深度集成的人机基础模型提供轨迹数据。

## 7. 优点

- **问题选得好**：聚焦"用户中途改变意图"这一真实且困难的社会智能挑战，而非单纯提升物理技能。
- **闭环评测设计**：自建 Core28 模拟器基准，agent 通过与真机完全相同的工具接口完成端到端任务，比静态 VQA 评测有说服力。
- **合成数据管线严谨**：状态机保证工具调用正确性，教师 LLM 生成语言，叠加规则检查 + 两阶段 LLM 评判 + 修订机制，质量可控。
- **工程细节扎实**：非阻塞上下文压缩、视觉预填充、FIFO 语音队列、运行时动态 schema 等设计均针对实时交互痛点。
- **模块解耦与可扩展**：VLA 技能以注册表形式动态暴露为工具参数，新增操作技能无需重训 agent。
- **仿真与真机结合**：Isaac Sim 标定细致，且明确承认仿真排名不能完全替代真机验证，态度客观。

## 8. 不足与局限

- **架构层面**：集成是"操作性"而非"学到的"——语音、记忆、导航、操作分散在不同组件，经由模型调用和工具协调可能引入上下文丢失、延迟、脆弱的交接与行为碎片化；系统缺乏对用户、环境和机器人物理状态的统一表征。
- **数据层面**：训练数据完全合成，虽经质量门但可能无法完全反映真实用户口语的多样性与噪声；场景镜像部署环境，存在过拟合风险。
- **实验层面**：Core28 规模小；缺少消融实验（如 harness 各组件、上下文压缩、异步语音的贡献度）；真实机器人证据仅一个演示；对"哪种失败模式在真机上会更严重"缺乏讨论。
- **基准可靠性**：LLM 评判可翻案口语语义门，尽管有限制，仍引入一定主观性；模拟器与真机之间的 sim-to-real 差距未系统量化。
- **应用限制**：依赖静态关键点地图（无法自由探索新环境）；VLA 技能限于已训练的拾放场景；本地 GPU 工作站运行，设备成本与边缘部署可行性未讨论；系统未涉及多用户社交场景、情绪或非语言行为（如注视、手势）等更广泛的社会智能维度。
