## 摘要
近年来，由多模态大语言模型（MLLM）驱动的智能体系统发展迅速，但现有的具身智能体基准仍然缺乏对多智能体协调的细粒度诊断。大多数基准要么关注单智能体任务完成情况，要么用整体任务成功率来概括多智能体行为，这可能会掩盖协调失败，例如重复工作、违反顺序约束、资源竞争和交接不同步。在本文中，我们介绍了CoCoBench，这是一个用于评估可执行家务任务中多智能体具身协调的结构级基准。CoCoBench包含897个经过oracle验证的实例，围绕四个反复出现的协调结构组织：任务分配、顺序排序、互斥和交接协调。除了任务成功率外，CoCoBench还提供结构级分数，用于衡量智能体是否有效协调。我们评估了11个领先的MLLM，涵盖不同的协调模式、观察输入和智能体数量。结果表明，协调能力高度特定于结构：整体表现强劲并不意味着在不同协调类型上具备均衡的能力。这些发现为设计有针对性的模型架构和提高多智能体协调能力指明了新方向。

## Abstract
Agent systems powered by multimodal large language models (MLLMs) have advanced rapidly in recent years, yet existing embodied-agent benchmarks still lack fine-grained diagnostics for multi-agent coordination. Most benchmarks either focus on single-agent task completion or summarize multi-agent behavior with overall task success rates, which can obscure coordination failures such as duplicated work, violations of ordering constraints, resource contention, and desynchronized handoffs. In this paper, we introduce CoCoBench, a construct-level benchmark for evaluating multi-agent embodied coordination in executable household tasks. CoCoBench contains 897 oracle-validated instances organized around four recurring coordination constructs: task allocation, sequential ordering, mutual exclusion, and handoff coordination. In addition to task success rate, CoCoBench provides construct-level scores that measure whether agents coordinate effectively. We evaluate 11 leading MLLMs across different coordination modes, observation inputs, and numbers of agents. The results show that coordination ability is highly construct-specific: strong overall performance does not imply balanced competence across different coordination types. These findings point to new directions for designing targeted model architectures and improving multi-agent coordination ability.

## 2. 方法论：核心思想、关键技术细节

### 2.1 问题形式化

- 将多智能体具身协调建模为**轨迹级联合规划**问题：
  - 任务实例定义为 `x = (E, A, S, O, U, Δ, Φ, H, d)`；
  - 每个智能体在步骤 `t` 获得观测 `o_i^t`，高层协调策略 π 根据所有智能体的观测历史输出联合技能决策 `u_t = (u_1^t,…,u_N^t)`；
  - 执行器（executor）返回执行事件，形成轨迹 `τ`；
  - 任务成功由目标谓词是否全部满足判定：`Succ_x(τ) = 1[∀φ∈Φ, φ(s_H)=1]`。
- **协调耦合定义**：当某个智能体的技能改变了另一个智能体技能的有效性/收益/成本时，任务即存在协调耦合（见公式 5）。CoCoBench 将这类耦合具体化为可测量的任务族，并沿两条互补轴评估：`Eval(π;x) = (Succ_x(τ), C_{d,x}(τ))`。

### 2.2 四种协调构造与评分函数

- **D1：任务分配（Task Allocation）**
  - 目标：并行子任务被均衡分配，避免重复或串行化。
  - 分数：`C_D1 = min(1, M*/M)`，其中 `M` 为实际 makespan，`M*` 为 oracle/参考 makespan。
- **D2：顺序排序（Sequential Ordering）**
  - 目标：遵守因果顺序，如先开容器、全部放入、最后关闭。
  - 分数：`C_D2 = p_legal * (1 - v/n)`，其中 `n` 为顺序相关操作数，`v` 为排序违规数，`p_legal∈{1,0.5}` 为合法性门。
- **D3：互斥（Mutual Exclusion）**
  - 目标：对共享独占工具进行无冲突调度。
  - 分数：`C_D3 = (1 - c/a) * min(1, M*/L)`，`a` 为资源访问次数，`c` 为冲突次数，`L` 为执行步数，`M*` 为参考 makespan。
- **D4：交接协调（Handoff Coordination）**
  - 目标：生产者—消费者模式中，缓冲区不溢出且消费者不空等。
  - 分数：`C_D4 = 1 - min(1, (o+w)/h)`，`h` 为成功交接数，`o` 为溢出事件数，`w` 为空缓冲等待事件数。
- 上述分数均为**轨迹级确定性计算**，与最终任务成功与否解耦；高 CS 不意味着任务成功，反之亦然。

### 2.3 基准实例化与质量控制

- 平台：**AI2-THOR** 仿真环境。
- 任务族：10 种家务任务类型，覆盖食物存储、物品整理、柜子装载、食物准备、物品搬运等。
- 实例规模：897 个实例，四类构造分布较均衡（D1: 218，D2: 225，D3: 230，D4: 224）；团队大小为 2/3/4（415/288/194 个实例）。
- **三重质量控制门**：
  1. **放置门**：验证物体可用性、空间可行性和交互能力；
  2. **Oracle 门**：用特权参考策略确认任务可解；
  3. **度量门**：保留 oracle 轨迹能达到接近满分构造分数的实例。
- 所有任务共享**固定高层技能接口**（导航、拾取、放置、开/关、切片、等待等），从而将评测聚焦于高层团队规划而非低层技能执行。

### 2.4 评估协议设计

- 支持三种策略协议：**集中式（C0）**、**分散式无通信**、**分散式有广播通信**。
- 支持 **图像观测** 与 **盲观测（blind）** 两种输入设置。
- 动作菜单是任务、角色、状态相关的；D4 使用角色条件化菜单区分生产者/消费者。
- 执行器固定，多智能体并发决策时从同一状态快照选择动作，再按确定性顺序执行，保证可复现且能暴露冲突。

## 6. 主要结论与发现

- **协调能力高度构造特异**：没有模型在所有构造上同时领先。例如：
  - GPT-5.6-sol 总体最强（SR 84.8%，CS 0.90），在 D3/D4 上领先；
  - Qwen3-VL-8B 在 D1 上获得最高 SR/CS（95.0%/0.91）；
  - Claude Opus 4.8 在 D2 上领先（94.7% SR，CS 1.00）。
- **整体表现不等于均衡能力**：强模型可能在某类协调上较弱，弱模型也可能在某些构造上表现出色。
- **集中式状态聚合仍然重要**：集中式平均 48.0% SR / 0.69 CS，优于分散式+通信（39.6% / 0.65）和无通信（36.7% / 0.63）；通信只能部分弥补集中式信息融合的收益。
- **符号规划是

符号规划是主要瓶颈：图像观测相比盲设定仅带来少量提升（例如SR从45.2%→48.0%，CS从0.65→0.69），说明视觉感知并非当前协调失败的主因；真正的限制在于模型对任务依赖关系、资源互斥、交接协议等符号化规则的理解与规划能力不足。

- **构造分数（CS）与任务成功率（SR）具有互补性**：在GPT-5.6-sol的轨迹上，四种构造分数之间的Pearson相关系数最高仅0.29（D2与D3），且多数低于0.1，证明CS各维度确实刻画了不同的协调机制。同时，CS与SR的差异暴露了几类典型模式：
  - 高SR低CS：任务成功但协调笨拙，如重复劳动、长时间互斥等待、缓冲区反复溢出；这类缺陷被传统指标完全掩盖。
  - 低SR高CS：协调过程良好但最终因小概率执行错误（如某一步放置失败）导致目标未达成；这提示CS可作为过程质量的有效补充信号。
- **团队规模影响显著**：从2智能体到4智能体，平均SR从约55%降至约38%，CS从约0.74降至约0.60；D3（互斥）和D4（交接）对团队规模最敏感，而D1（并行分配）的相对下降较小，说明资源争用与同步问题随规模非线性恶化。
- **失败模式分析显示，正常终止率偏低**：整体约43%的轨迹因预算耗尽而失败，约12%因协议错误（如非法动作序列）中止；多数模型在D2和D4上的合法计划率低于70%，即便最终SR较高，也存在大量“边试边改”的非规范操作。

## 7. 局限性与改进空间

- **仿真环境与真实世界的差距**：任务基于AI2-THOR的简化物理与固定技能接口，物体可交互性完全由门控机制保证，无法覆盖真实机器人面临的不确定性、感知噪声、执行误差和物理形变。
- **高层规划与底层执行的脱钩**：技能接口是黑盒执行器，动作菜单限定了可能性；虽然这有利于标准化评测，但忽略了底层技能失败对协调策略的反馈影响，也无法考察端到端多智能体协作。
- **协调分数设计的敏感性**：CS计算依赖于参考makespan `M*`或`L`等基准值，这些基准由oracle轨迹确定，可能低估或高估复杂场景的合理协调质量；另外，D2的`p_legal`惩罚项仅区分合法/半合法，对“顺序部分违规”的量化仍较粗糙。
- **通信协议受限**：分散式通信只支持广播机制，未模拟有限带宽、噪声或定向消息传递；真实系统中的通信成本与信息不完备问题未被纳入评估。
- **模型版本与封闭性**：专有模型（如GPT-5.6-sol）为论文中代号，API版本可能频繁更新，导致结果难以精确复现；且不同模型预处理条件、上下文长度、输出格式各异，可能引入隐性偏差。

## 8. 思考与展望

- 该基准对多智能体协调能力的“构造级诊断”思路值得借鉴，尤其是将任务成功与过程质量解耦的评分框架，为未来具身多智能体评测提供了新范式。
- 后续工作可考虑：
  - 引入更丰富的环境状态（如部分可观测、随机转移）和连续动作空间；
  - 支持端到端学习型协调策略，而非仅高层语义决策；
  - 将单一构造扩展为复合构造，考察多个协调机制耦合时的综合表现；
  - 增加跨Embodiment（异构机器人）协调场景，使基准更具现实应用价值。

**总体评价**：CoCoBench是一篇组织严谨、量化手段丰富的基准论文。它在多智能体具身协调的“过程质量”评测上迈出了重要一步，弥补了现有指标只重结果不重机制的缺陷。虽然存在仿真简化、分数设计依赖参考基准等问题，但其构造化思路和公开的评测协议对后续研究具有较高的参考意义。
