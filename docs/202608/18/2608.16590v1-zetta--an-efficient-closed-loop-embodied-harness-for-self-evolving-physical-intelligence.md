## 摘要
具身智能体越来越多地被用来弥补端到端策略模型留下的差距。然而，智能体路径尚未在物理执行中实现闭环学习：现有的操控系统大多保持开环，在滚动执行期间遵循固定技能，并且只在回合结束后进行反思。这种事后反思无法在执行过程中进行控制，因为物理交互要求决策以超越当今大型智能体模型的频率跟踪快速变化的机器人-环境状态。我们提出了Zetta，一种闭环具身操控系统，它在保持基础策略冻结的同时，在线演化基于代码的运行时批评器和恢复技能。通过三个时间尺度分离的循环，Zetta提供了动作频率治理、滚动级批评-恢复提议和验证门控的技能更新。结合Z-Infra（一种将智能体逻辑与异构执行资源解耦的滚动基础设施），Zetta在我们当前的滚动预算下在LIBERO-Pro和RoboCasa上取得了最先进的成功，分别达到90.8%和93.6%，推理速度提升11.1倍；成功率随着自我探索经验持续提升；学到的技能可以零样本迁移，并且出现了清晰的机器人‘顿悟时刻’。这些结果表明，闭环操控系统的自我进化为可靠的物理智能开辟了一条扩展路径。

## Abstract
Embodied agents are increasingly used to close the gap left by end-to-end policy models. Yet the agentic path has not realized closed-loop learning in physical execution: existing harnesses remain largely open-loop, following fixed skills during rollout and reflecting only after an episode completes. Such post-hoc reflection cannot govern execution as it unfolds, because physical interaction requires decisions to track rapidly changing robot-environment states at a frequency beyond today's large agentic models. We present Zetta, a closed-loop embodied harness that evolves code-based runtime critics and recovery skills online while keeping the base policy frozen. Through three timescale-separated loops, Zetta provides action-frequency governance, rollout-level critic-recovery proposal, and validation-gated skill updates. Together with Z-Infra, a rollout infrastructure decoupling agent logic from heterogeneous execution resources, Zetta achieves state-of-the-art success on LIBERO-Pro and RoboCasa under our current rollout budget, reaching 90.8% and 93.6%, with an 11.1x inference speedup; success continues to scale with self-exploration experience; learned skills transfer zero-shot, and clear robotic "Aha Moments" emerge. These results show that closed-loop harness self-evolution opens a scaling path for reliable physical intelligence.

## 2. 论文提出的方法论

### 2.1 核心思想

Zetta的核心架构定义为可进化操控系统 H = {C, R, T}：
- **运行时批评者（Runtime Critic, C）**：一组高频监测函数，持续扫描轨迹，生成结构化提议 Pt = ⟨et, σ̂t⟩，其中 et 是可审计的失败证据，σ̂t 是建议执行模式。
- **恢复手册（Recovery Playbook, R）**：将具体因果失败机制映射到可执行恢复策略的结构化库。
- **异构工具集（Heterogeneous Toolset, T）**：可生成、实例化、选择与精炼的可执行工具（如规划器、抓取检测器、恢复模块）。

### 2.2 三个时间尺度分离的循环

Zetta通过三个协同循环实现闭环自进化：

**Loop 1 — 批评者治理的动作循环（Critic-Governed Action Loop）**
- 在动作执行频率上运行运行时批评者，持续监控物理执行状态；一旦偏离名义分布，立即触发相应恢复技能。运行期间，在线编排者（Orchestrator Agent Aorch）作为固定推理算子，审核证据并批准模式转换。
- 决策公式：σt = Aorch(Pt, R, T, K)，其中σt=0表示VLA/WAM执行，σt>0表示调用专用工具。
- 关键保障：**VLA重新进入契约（Re-entry Contract）**，定义逻辑谓词 Ψ(st) = 𝟙(FailureCleared) ∧ 𝟙(Stability(st) > γ)，确保只有在失败证据被消除、物理状态达平衡后，才将控制权交还VLA。

**Loop 2 — 滚动批次候选优化循环（Rollout-Batch Candidate Optimization Loop）**
- 对每次迭代的失败轨迹进行聚类和因果诊断，提出候选批评者与恢复方案。
- 借鉴SkillOpt与EmbodiSkill的SGD式优化思路，在代码空间中进行有界、稳定的增量更新。
- 采用**自顶向下的分层因果诊断**（Top-Down Hierarchical Causal Diagnosis），按优先级遍历：Evaluation → Critic → State → Planning → Recovery → Parameter，遵循“高层逻辑能解决就不改低层参数”的最小干预原则。

**Loop 3 — 验证门控技能更新循环（Validation-Gated Skill Update Loop）**
- 仅接受经过验证、能提升成功率且在多个滚动中泛化的批评者与恢复候选，将其加入技能记忆。
- 每个候选需通过：① 历史回归测试（原始失败种子100%解决）② 孤立数据集上的留出评估（Held-out Evaluation）。

### 2.3 三阶段进化流程

- **Phase I（失败画像）**：大规模采样建立VLA纯执行基线；通过First Missing Milestone (m*) 定位失败阶段；区分基础设施失效vs策略失效。
- **Phase II（诊断与修复）**：基于Earliest Observable Divergence (EOD) 进行机制级失败聚类；选择medoid种子进行单视图接地诊断；实施最小化修补（含批评者增强、恢复起草、工具适配）。
- **Phase III（泛化与打包）**：将种子级补丁合并为统一版本化操控系统包 Hmerged = {Cmerged, Rmerged, Tmerged}，分为 SKILL.md、tools/、plans/、params/ 四个目录；执行严格的双评估协议。

### 2.4 Z-Infra 滚动基础设施

首次为自进化具身智能体设计的滚动基础设施，三层架构：
- **控制平面（Control Plane）**：统一API入口，负责路由、资源管理、故障容错。
- **环境工作者层（Environment Worker Layer）**：管理异构模拟环境生命周期；实现资源共享组（Resource-Sharing Group），通过模型模板复用+线程池并行加速。
- **滚动工作者层（Rollout Worker Layer）**：GPU驻留模型服务，支持动态批处理、模型分区（VLM与AE分离部署，通过CUDA IPC传输）、量化运行时（W8A8等）。

核心思想：**抽象层解耦**——智能体逻辑与硬件资源管理完全解耦，跨异构环境、模型、CPU/GPU透明扩展。

6. **Z-Infra吞吐量提升**：有效吞吐量从1.7→35.1 episodes/min（20.6×提升），并发16时比无Z-Infra高7.7×，比RPent高12.8×。

1. **首次实现闭环具身自进化**：区别于传统事后反思范式，通过三时间尺度分离的循环实现了执行中的高频治理，是领域内的概念性突破。
2. **保持基座策略冻结**：所有提升来自操控系统（批评者+恢复+工具）的进化，不改变π0.5/GR00T的参数——体现了“最小干预、顶层治理”的设计哲学。
3. **严格的验证门控协议**：历史回归（100%解决原失败）+ 留出集评估双重保障，防止过拟合修复损害泛化性；种子重分类机制确保了数据隔离的纪律性。
4. **层次化因果诊断**：自顶向下的分层逻辑有效避免“过度参数化修复”导致的全局性能退化。
5. **Z-Infra的基础设施创新**：模型分区（VLM/AE分离）、量化运行时（W8A8 co-design）、资源共享组、动态批处理等设计针对具身滚动负载特性，吞吐量提升显著。
6. **Aha时刻的洞察深刻**：揭示了物理智能的“可扩展单元”——可复用的失败状态→恢复行为映射，而非任务特定轨迹。
7. **实验设计规范**：严格隔离开发/测试种子、同种子对比隔离机制贡献、清晰的任务命名与代码结构（Algorithm 1/2）保障可复现性。

## 8. 不足与局限

1. **仅限模拟环境**：所有实验均在MuJoCo/robosuite（LIBERO、RoboCasa）中进行，未验证真实机器人部署。模拟与实体之间的Sim-to-Real差距尚未处理。
2. **基座策略覆盖有限**：仅验证了π0.5和GR00T N1.5两个模型，CRT/SOTA WAM等更广泛模型族未覆盖；泛化结论受限。
3. **缺少系统消融**：未逐一量化批评者、恢复手册、分层诊断、量化分区、模型分区等组件的独立贡献，也缺乏与更多自进化系统（ENPIRE、Guava等）的直接对比。
4. **统计显著性不足**：除部分Wilson置信区间外，主要报告点估计值，未提供方差分析和置信区间。
5. **LLM失败风险未充分讨论**：Aorch和Aevo依赖LLM，在诊断过程中的幻觉风险、证据chain的可靠性虽有所缓解（单视图协议、分层逻辑），但定量鲁棒性分析不足。
6. **可扩展性上限未探索**：进化依赖人工参与的环节（如“确定medoid seed进行诊断”）在更大规模任务库中的自动化程度有待讨论。
7. **论文标注“under review”尚未正式发表**：部分数据和结论尚未经受同行评审的严格检验。
