## 摘要
在多样化任务中构建可靠的机器人能力，需要投入大量人力来开发和维护技能、设计奖励，并将感知与控制集成起来。我们提出 Reconstruct, Practice, Go Real (RPG)，一个无需更新模型权重即可自主改进机器人执行系统的框架。RPG 在离线数据集中识别操作能力，并在仿真中构建相关的练习任务。在练习过程中，RPG 利用执行反馈、特权仿真器状态和可用数据集视频来诊断失败。它基于这些诊断开发新的可复用符号技能，改进现有技能，并修订系统提示词。跨任务评估会测试单个候选变更和合并修订，然后才将其保留以供复用。在测试时，多模态 LLM 使用生成的系统提示词和技能库来协调感知与机器人控制。在 22 个操作任务的留出初始化设置上，RPG 将任务成功率从第一轮练习后的 28.6% 提升到 15 轮后的 95.0%，优于所有评估基线，包括 ASPIRE（75.5%）和由 GPT-6 Astra Pro 驱动的 CaP-Agent0（60.0%）。经过统一的校准与硬件适配流程后，该冻结系统在所有 30 次物理试验中均取得成功，三个任务各进行十次试验。项目网站：https://rpg-robot.github.io/

## Abstract
Building reliable robot capabilities across diverse tasks requires substantial human effort to develop and maintain skills, design rewards, and integrate perception with control. We present Reconstruct, Practice, Go Real (RPG), a framework for autonomous improvement of robot execution systems without updating model weights. RPG identifies manipulation capabilities in an offline dataset and constructs related practice tasks in simulation. During practice, RPG uses execution feedback, privileged simulator state, and available dataset videos to diagnose failures. It develops new reusable symbolic skills, refines existing skills, and revises the system prompt based on these diagnoses. Cross-task evaluation tests individual candidate changes and merged revisions before they are retained for reuse. At test time, a multimodal LLM uses the resulting system prompt and skill library to coordinate perception and robot control. On held-out initializations of 22 manipulation tasks, RPG improves task success from 28.6% after the first practice round to 95.0% after 15 rounds, outperforming all evaluated baselines, including ASPIRE (75.5%) and CaP-Agent0 powered by GPT-6 Astra Pro (60.0%). After a common calibration and hardware-adaptation procedure, the frozen system succeeds in all 30 physical trials, with ten trials on each of three tasks. Project Website: https://rpg-robot.github.io/

## 1. 核心问题与整体含义

- **研究动机**：在多样化任务上构建可靠的机器人能力，需要大量人工投入——开发与维护技能、设计奖励函数、把感知与控制集成起来，成本高且难以跨任务复用。
- **核心矛盾**：现有 LLM 机器人控制范式存在取舍：
  - **Code-as-Policy**（CaP-X、ProgPrompt 等）：把感知与控制原语写成可执行程序，执行高效、可含反馈循环，但行为依赖显式程序逻辑与感知接口，某些符号判据（如"抓取是否成功"）难以稳健编写。
  - **Agent-as-Policy**（PaLM-E 等）：MLLM 留在控制回路中，视觉/语义推理灵活，但频繁模型调用使底层决策缓慢。
- **论文主张**：可扩展系统应"把可重复执行交给可复用代码，把需要视觉/语义判断的决策留给多模态推理"。RPG 因此**不更新模型权重**，而是把改进目标放在两个可持久化的共享组件上：**共享技能库**与**系统提示词**。
- **整体含义**：提出一条"离线数据 → 仿真练习 → 自主诊断与修订 → 冻结部署"的自我改进路径，使机器人在无人工逐任务工程的情况下持续提升执行系统。

## 2. 方法论

### 2.1 核心思想
- 系统建模为 Agent-as-Policy：$S_r = (\mathcal{L}_r, \rho_r)$，$\mathcal{L}_r$ 为共享技能库，$\rho_r$ 为系统提示词；技能接收参数（手臂、目标位置等），执行动作序列并返回退出状态与实测效果。
- 三个阶段的六个专用智能体：**Constructor、Runtime Agent、Privileged Agent、Video Analyzer、Implementor、Merger**。
- 初始库 $\mathcal{L}_0$ 含来自 CaP-X 的 9 个底层工具 + 6 个高层技能（pick、place、pick-and-place、双臂桌面支撑转移、move-above、push），共 15 项。

### 2.2 Reconstruct：构建并冻结练习任务
- 从离线数据集 $\mathcal{D}$（本文用 ABC，覆盖 193 个任务）中选取源任务，每个源任务挑 3–8 条轨迹，审阅视频与文本描述，识别所体现的操作能力，并**提出一个仿真练习任务**（MuJoCo + YAM 机器人模型，每个源任务 7.5 分钟预算）。
- 练习任务**不必复现源任务或其场景几何**，可只覆盖部分能力或做类比迁移：
  - 整理太阳镜 → 关闭已装载的眼镜盒；整理化妆品 → 关闭抽屉；卷毛巾 → 折叠一次。
  - 无对应源任务者直接使用已有任务规格。
- Constructor 为每任务编写 `check_success` 实现二元评估器 $e_i(\tau)$，由人工核验其是否度量了所提目标。
- **任务定义与评估器在 Practice 开始前冻结**，任务集合可随更多源任务持续扩展。

### 2.3 Practice：从执行中改进系统（每轮流程）
1. **执行**：Runtime Agent 仅凭部署可得的观测与执行历史，对每任务尝试 5 次；Privileged Agent 用**同一模型与同一技能库**，但额外接收仿真器状态（物体名称、位姿、尺寸、速度、布角位置），从相同初始状态并行运行。技能本身不使用特权信息。
2. **诊断**：Video Analyzer 对开发任务上失败的 Runtime 执行，与 Privileged 执行及数据集源视频对比；输入含采样帧、技能调用与返回值、感知结果、指令与实测机器人状态、仿真真值、评估器指标。它定位**首个可观测失败**、给出成因与具体修改建议（附帧或轨迹证据），但不直接改系统。
3. **修订**：Implementor 接收 $S_r$、执行记录与诊断建议，提出新技能、修改现有技能、修订系统提示词；每个未达 5/5 的开发任务**至多产生一个候选**，所有候选独立从 $S_r$ 分支；提交前检查可加载性、语法与接口合法性、以及是否仅依赖部署可得观测。
4. **候选跨任务验证**（门控公式）：在 22 个任务 × 5 个固定开发种子上用 Runtime Agent 评测（每系统 110 回合）：
   - $\hat q_i(S)=\frac{1}{5}\sum_{k=1}^{5} e_i(\tau_{ik}(S))$，$\hat J(S)=\frac{1}{K}\sum_{i=1}^{K}\hat q_i(S)$，$K=22$。
   - $\mathrm{Gate}(\tilde S;S_r)=1 \iff \Delta\hat J>0 \ \wedge\ \min_i \Delta \hat q_i \ge -0.20$。
   - 即：**平均成功率必须上升，且任一任务不得掉超过 1/5（20 个百分点）**。
5. **贪心合并与重测**：合格候选按 $\Delta\hat J$ 排序，逐个贪心集成（每轮最多 8 次集成尝试）；同文件冲突先做三方合并，机械合并失败则由编码智能体解决；合并系统 $S^+$ 再用**同一门控**相对 $S_r$ 复测，通过且决定保留则 $S_{r+1}=S^+$，否则 $S_{r+1}=S_r$（回滚保护）。
- 共执行 **15 轮**；人工只负责环境搭建、评估器核验、决定停止练习与硬件适配。

### 2.4 Go Real：适配并冻结部署
- RPG 与基线 CaP-Agent0 接受**相同的坐标标定与硬件适配**（垫片偏移、空夹爪开口），不做任何物体或任务特定调参。
- 物理评测统一使用低推理强度以降低时延；**Privileged Agent 与 Video Analyzer 在部署时不使用**。
