## 摘要
视觉-语言-动作模型和世界-动作模型已在机器人领域展现出令人印象深刻的能力，但泛化到未见任务仍然具有挑战性。近来，通用多模态智能体在零样本机器人任务求解方面展现出巨大潜力。然而，它们通常需要从头推理并探索物理世界，因而产生高昂的执行成本。为降低这些成本，我们提出了 RoboSkill，一个通过“探索、执行、演化”闭环将技能获取与技能复用连接起来的框架。在该闭环中，智能体通过探索收集任务相关信息，在执行任务时适应反馈，并根据执行记录演化其技能库。随后，它复用这些技能来指导下一轮循环中的探索与执行，从而闭合整个回路。为提高闭环效率，我们引入触觉反馈补充视觉信息，以减少物理交互过程中的不确定性。我们进一步用可复用代码增强文本指导，以减少技能复用期间的推理开销。在 LIBERO-10 上，RoboSkill 在四个智能体上将首回合成功率提升 12.5--25.0 个百分点，并将平均运行时间降低 7.6--72.4%。在真实机器人上，它将成功率提升 8.3 个百分点，并将成功试验的平均运行时间至少降低 14.4%。

## Abstract
Vision-language-action and world-action models have demonstrated impressive capabilities in robotics, yet generalization to unseen tasks remains challenging. More recently, general-purpose multimodal agents have shown great potential for zero-shot robotic task solving. However, they often incur high execution costs by reasoning and exploring the physical world from scratch. To reduce these costs, we introduce RoboSkill, a framework that connects skill acquisition and reuse through an Explore, Execute, Evolve loop. Within this loop, the agent explores to gather task-relevant information, executes tasks while adapting to feedback, and evolves its skill library based on execution records. It then reuses these skills to guide exploration and execution in the next cycle, closing the loop. To improve loop efficiency, we complement vision with tactile feedback to reduce uncertainty during physical interaction. We further augment textual guidance with reusable code to reduce reasoning overhead during skill reuse. On LIBERO-10, RoboSkill improves first-episode success rates by 12.5--25.0 percentage points and reduces average runtime by 7.6--72.4% across four agents. On real robots, it improves success rates by 8.3 percentage points and reduces average runtime for successful trials by at least 14.4%.

# 论文总结：Explore, Execute, Evolve —— 面向具身智能体的技能获取与复用闭环（RoboSkill）

## 1. 核心问题与研究动机

- **背景**：VLA（视觉-语言-动作）模型与世界-动作模型（WAM）虽已支持快速任务执行，但其能力仍主要受训练数据与任务分布约束，**泛化到未见任务依然困难**。
- **新路径**：通用多模态智能体（如编码/交互式智能体）开始展现跨任务零样本求解能力，但**代价高昂**——每次执行基本"从零开始"，需重复感知、物理试错与失败恢复。
- **软件智能体的启发与差异**：Web/GUI/编码智能体可将交互历史蒸馏为可复用技能；但具身交互有本质不同：
  - 观测是**部分的**、场景是**变化的**、约束**依赖具体本体**；
  - 执行结果**不确定**：下达指令不保证产生预期物理效果；
  - 因此复用技能**不能只是重放固定计划**，智能体必须补全缺失信息、验证物理结果、在偏离计划时恢复。
- **核心命题**：如何把"技能获取"与"技能复用"连成闭环，从而降低具身智能体从零推理与探索的开销。

## 2. 方法论

### 2.1 核心思想
- 提出 **RoboSkill** 框架，围绕 **Explore（探索）– Execute（执行）– Evolve（演化）** 闭环组织：
  - 探索获取缺失信息 → 执行中适应反馈 → 依据执行记录把经验固化为技能 → 技能反过来指导下一轮探索与执行，从而闭合回路。

### 2.2 三个环节的关键细节

- **框架总览**：智能体接收"任务指令 + 被选中的技能 + 通过 SDK 访问环境"；需要信息时先求解探索子任务，再用获得的知识与技能生成并运行代码，通过 SDK 执行动作、获取观测，并根据反馈继续或修正执行；结束时进入演化阶段，审阅会话记录与实际执行的代码，构建/更新技能。
- **探索（Exploration）**：
  - 把"获取信息"形式化为**探索子任务**，其即时目标不同于主任务，但服务于主任务的可靠高效完成；
  - 探索自身也是**多轮执行—反馈的嵌套循环**；
  - 示例：移动奶油奶酪时抓取失败 → 演化指出"桌面高度"是未解决问题 → 用 RGB-D 估计仍不确定 → **下压至接触**得到高度 ≈0.446 m → 指导后续抓取。
  - 探索结论作为"当前任务知识"保留在会话上下文中；若中途退出，则由框架调用智能体**自我审阅**，按演化流程固化为技能包。
- **闭环执行（Closed-loop Execution）**：
  - 上下文包含：任务指令、机器人控制/感知 API 规范、探索知识、被选技能包；
  - 观测 = RGB + 深度 + **触觉**（压力、力/力矩信号），触觉提供图像难以判断的接触/碰撞证据；
  - **基于 SDK 而非固定工具集**：智能体可自行组合 SDK 调用与数据处理，产出可复用过程代码（如 `depth_pointcloud.py`、`verify_table_height.py`）；
  - 全程记录交互与执行的代码，作为演化的输入。
- **演化（Evolution）**：
  - **时机**：不为每个子任务单独复盘（开销大），而是在任务结束、智能体退出时做**一次性审阅**汇总；
  - **技能结构**：① 文本指导（任务策略、适用条件、失败教训）；② 可复用代码（组织为层级结构）；③ 支撑记录（失败案例与纠正策略、完整执行轨迹、元数据含简要描述与视觉关键帧）；
  - 智能体**充当自己的审阅者**，从会话记录与实际执行的代码中抽取整合；已有对应技能则补充，否则新建技能包；
  - **技能使用**：智能体检视元数据并选择最多 **K=3** 个相关技能包（实验设定），放入新任务智能体的工作区。

### 2.3 两个关键设计选择
- **触觉反馈**：补充视觉，降低物理交互中的不确定性；
- **技能内嵌可复用代码**：文本描述策略与适用条件，代码保留可适配到相关场景/任务的过程，降低复用时的推理开销。

## 3. 实验设计

### 3.1 仿真场景
- **Benchmark**：**LIBERO-10** 的 10 个任务；
- **主对比协议**：每任务 4 个评估种子（排除技能构建所用的种子 0），每条件 **40 个 task–seed 单元**；每单元 **4 小时**预算，允许包含多回合（首次尝试为 Episode 1，每次 `reset` 开启新回合）；单元在成功、智能体自行退出或超时结束；
- 跨任务/跨智能体迁移使用全部 5 个种子（0–4），每条件 **50 个单元**；
- 技能迭代实验另用种子 100–104 的独立评估集，所有条件（含 Baseline）在该集上重跑。

### 3.2 真实机器人场景
- **硬件**：5 个并行工站，每站 Piper 机械臂（仅用右臂）、双指触觉传感器夹爪、腕部相机、外部俯视第三人称相机；

## 6. 主要结论与发现

- **主结果（仿真）**：技能复用普遍提升成功率与效率。Sol Final SR 82.5%→97.5%、SR@30m 32.5%→72.5%、Avg. Ep. 9.2→2.9、Avg. Time 94.5→35.9 min；Opus SR@30m 17.5%→82.5%、耗时 80.9→22.3 min；Astra 1st SR 72.5%→97.5%（Final SR 已饱和仍提升效率）；Fable Final SR 97.5%→100%。
- **主结果（真机）**：Astra 易任务 91.7%→100.0%、难任务 80.0%→88.3%；成功试验平均耗时分别由 20.3→16.6 min、27.0→23.1 min。
- **跨任务迁移**：仅给异任务技能也有帮助（Sol 1st SR 30%→44%、耗时 86→66.3 min；

Fable 的 Final SR 与耗时亦有改善），说明即使技能来自**不同任务**，其中蕴含的通用操作过程知识（如抓取前的接触验证、失败后的恢复流程、传感器数据的处理代码）仍可被部分复用，只是增益显著弱于同任务技能。这支持了"技能内容而非仅技能数量起作用"的直觉，但由于缺少"仅数量不相关内容"的对照条件，该结论仍无法被严格隔离验证。

- **跨智能体迁移**：仿真中，为 Astra/Sol 构建的技能包交由 **Kimi K3** 使用后，其在 50 个单元上的表现优于无技能 Baseline，表明技能包中的**文本指导 + 可复用代码**并非绑定于特定模型的私有提示，而具有跨模型的可读性与可移植性；真机上由 Astra 演化出的技能交给 Sol 使用同样获得成功率提升。不过跨智能体增益通常小于同智能体自用，暗示技能中的措辞与代码组织方式仍隐含原智能体的行为偏好。
- **技能演化/迭代更新**：在独立的种子 100–104 评估集上，随着演化轮次增加，多数智能体的成功率与效率呈上升趋势，说明"执行记录 → 自我审阅 → 技能固化"的循环确实能持续积累有效经验；但更新并非单调改进，第二轮更新后部分智能体（如 Opus）的 SR@30m 与耗时出现回落，提示**技能库膨胀、冗余或相互冲突**可能引入新的决策负担，演化机制需要配套的裁剪与冲突消解策略。
- **消融一：可执行代码（w/o Code）**：去掉技能中的可复用代码、仅保留文本指导后，四个智能体的成功率与效率普遍下降，其中 1st SR 与 Avg. Time 的退化尤为明显。这说明"技能"的价值不只在策略层面的语言描述，**可被直接调用、适配的过程代码**显著降低了复用时的重新推理与实现成本。
- **消融二：触觉（w/o tactile）**：移除触觉（压力、力/力矩）信号后，仿真成功率下降，真机"取试管"任务的成功率亦明显降低。触觉在视觉难以判别的**接触建立、滑移与碰撞**场景中提供了关键证据，尤其在需要精细力控或验证"是否真正抓稳"的步骤上不可替代。
- **技能选择分析**：对智能体实际挑选的技能包进行分析可见，被选中的技能与当前任务在对象类别、操作动词、空间约束上具有较高语义相关性；但选择并非总是最优，存在选中弱相关技能或遗漏关键技能的情况，说明当前基于元数据（描述 + 视觉关键帧）的选择机制仍较粗糙。
- **真机逐任务结果**：12 个任务中多数在 RoboSkill 下获得提升，叠毛巾、装电池、调天平等需要多步精细操作的任务受益最大；而"从针眼取线"这一高精度任务反而由 7/10 降至 5/10，是**技能负迁移**的直接证据——既有技能中的先验可能误导智能体放弃必要的在线探索。

## 7. 局限与不足

- **缺少算力与成本报告**：无法评估演化复盘的 token 开销，也无法判断"减少探索"所节省的时间是否被"技能构建与审阅"的成本抵消。
- **实验设计存在混淆变量**：RoboSkill 与 RoboSkill − 同时改变了技能数量与技能内容；技能选择列表只能证明"提供了什么"，无法证明"实际使用了什么"，因而难以定位性能提升的确切来源。
- **指标解释存在歧义**：仿真中失败单元也被计入 Avg. Time，提前放弃的失败运行会人为拉低平均耗时，使"效率提升"的解读需谨慎。
- **真机规模有限**：每任务 10 次、迁移任务仅 5 次试验，成功由现场志愿者人工判定，统计功效与判定客观性均受限。
- **结果并非单调改善**：多个条件（Sol 的 1st SR、Opus 加代码后的 1st SR、演化第二轮后的 Opus、真机取线任务）出现退化，说明技能复用存在**负迁移风险**，框架尚不能保证"技能总是有益"。
- **未涉及安全性、技能冲突与长期维护**：技能库规模增长后的去重、版本管理与冲突检测未被讨论。

## 8. 总体评价与启示

- **贡献定位**：论文的主要贡献不在于新的 VLA/WAM 模型，而在于提出一个**围绕技能生命周期的具身智能体框架**——把"探索获取缺失信息""闭环执行中的反馈适应""任务结束后的自我审阅与技能固化"串联为可运行的系统，并在仿真与真机上给出较系统的验证。
- **最有价值的观察**：
  1. **技能 = 文本策略 + 可执行代码 + 支撑记录**的三元结构，比单纯的提示缓存或固定工具集更贴近具身交互的不确定性；
  2. **触觉是被低估的具身信号**，在视觉退化场景中承担关键的验证与恢复职能；
  3. **技能可跨任务、跨模型迁移**，说明其中包含相当程度的通用操作性知识。
- **方法学启示**：把"从零推理"替换为"检索并适配已有技能"，是降低具身智能体推理与试错成本的一条现实路径；但技能库的价值取决于**选择、裁剪与冲突消解**的质量，仅靠"更多技能"并不必然更好。
- **后续方向**：引入技能数量的独立对照条件以分离内容与数量的贡献；设计技能冲突检测与淘汰机制；把演化成本纳入统一的效率指标；在更大规模的真机样本与更严格的自动成功判定下复现结论。
