## 摘要
我们关注语言条件的基于流的操作，其中机器人流（机器人速度场）作为与具身无关、以运动为中心的表示，用于利用从多个机器人平台收集的数据。该任务至关重要，因为语言条件操作对于实际机器人系统必不可少，但扩展机器人基础模型仍受限于劳动密集型的特定具身数据收集。现有方法要么用稀疏关键点位移粗略近似机器人流，要么无法处理语言条件操作。为解决这一局限，我们提出 NarrativeFlow，它使用以语言为条件的流匹配公式，将机器人流建模为连续速度场。相应地，NarrativeFlow 生成与真实世界操作物理一致的机器人流。为验证 NarrativeFlow，我们在语言条件操作的标准数据集上进行了实验。实验结果表明，NarrativeFlow 在标准评估指标上优于代表性基线方法。此外，通过真实世界实验，我们表明 NarrativeFlow 在多个操作任务中比基线方法取得更高的成功率。项目页面见 https://shota0520.github.io/NarrativeFlow-project-page/

## Abstract
We focus on language-conditioned flow-based manipulation, where robot flows (robot velocity fields) serve as embodiment-agnostic, motion-centric representations for leveraging data collected from multiple robot platforms. This task is crucial because language-conditioned manipulation is essential for practical robotic systems, yet scaling robot foundation models remains limited by the labor-intensive collection of embodiment-specific data. Existing methods either coarsely approximate robot flows with sparse keypoint displacements, or cannot handle language-conditioned manipulation. To address this limitation, we propose NarrativeFlow, which models robot flows as continuous velocity fields using a flow-matching formulation conditioned on language. Accordingly, NarrativeFlow generates robot flows that are physically consistent with real-world manipulation. To validate NarrativeFlow, we have conducted experiments on standard datasets for language-conditioned manipulation. The experimental results show that NarrativeFlow outperforms representative baseline methods on standard evaluation metrics. Furthermore, through real-world experiments, we show that NarrativeFlow achieves higher success rates than baseline methods across multiple manipulation tasks. The project page is available at https://shota0520.github.io/NarrativeFlow-project-page/

## 1. 核心问题与整体含义

- **研究背景**：语言条件操作对制造、物流、医疗等实际机器人系统至关重要，但扩展机器人基础模型仍受限于**劳动密集的特定具身数据采集**。
- **核心思路**：机器人流（robot flow / 机器人速度场）可作为**与具身无关、以运动为中心**的中间表示，桥接视觉观察与机器人动作，并能从任意机器人视频中提取，从而利用多平台数据。
- **现有方法局限**：
  - 许多流式操作方法（如 FLIP、Im2Flow2Act）用**稀疏关键点位移**近似机器人流，假设位移确定性，只能粗略近似连续机器人运动。
  - Flow as Flow 可建模稠密速度场，但仅支持**目标条件**操作，无法处理语言条件设置。
  - 现有方法通常只使用主 flow 生成损失，**缺乏对任务相关语义的显式监督**，容易被背景、光照等任务无关视觉细节干扰。
- **论文含义**：提出 NarrativeFlow，将语言条件机器人流建模为**连续概率速度场**，用 flow-matching 生成物理一致的机器人运动，为跨平台语言条件操作提供可扩展表示。

## 2. 方法论

### 2.1 核心思想

- 输入：初始图像 \(I_0\) 与自然语言指令 \(\ell\)。
- 输出：机器人流（机器人速度场），随后由流条件操作策略输出末端执行器位姿。
- 假设：固定相机设置下末端执行器在初始图像中可见；论文聚焦机器人流生成子任务。

### 2.2 架构组成

- **视觉语言融合编码器**：
  - \(I_0\) 用 DINOv3-ViT-B/16 编码，\(\ell\) 用 Qwen3-Embedding-0.6B 编码。
  - 引入**两个子任务 token**（subtask tokens），与图像、语言嵌入拼接后送入 Transformer 编码器（4 层）。
  - 两个 token 分别输出 \(z^{(1)}_{st}\) 和 \(z^{(2)}_{st}\)：
    - \(z^{(1)}_{st}\) 用于条件化 Flow-as-Flow 模块；
    - \(z^{(2)}_{st}\) 用于计算 Narrative Delta 损失。
  - 分离设计旨在缓解两个下游目标之间的学习信号干扰。

- **Narrative Delta 损失（辅助目标）**：
  - 离线用多模态大模型（Qwen3.5-9B）给定 \(I_0\)、目标图像 \(G\) 和提示，生成 \(N_c=5\) 条任务相关场景变化描述。
  - 用 Qwen3-Embedding-0.6B 将描述嵌入为叙事表示 \(\{z^{(i)}_{ND}\}\)。
  - 损失定义为：
    \[
    \mathcal{L}_{ND}=\frac{1}{N_c}\sum_{i=1}^{N_c}\left[1-\text{cossim}\left(z^{(2)}_{st}, z^{(i)}_{ND}\right)\right]
    \]
  - 仅在训练时使用，推理时不需要 \(G\)。

- **Flow-as-Flow 模块**：
  - 在 \(I_0\) 上均匀初始化 \(N=10\times 10\) 个点，通过积分预测速度场获得未来位置。
  - 目标速度场带稳定项：
    \[
    v(\Xi_t, X, t)=\dot{\Xi}_t-k(X-\Xi_t)
    \]
    其中 \(X\sim\mathcal{N}(\Xi_t,\sigma_0^2 e^{-2kt}I)\)，\(k=1\)，\(\sigma_0=0.05\)。
  - 实现基于 Diffusion Transformer（DiT），用 adaLN-Zero 调制；条件向量由 \(z^{(1)}_{st}\)、\(I_0\)（ResNet-18 编码）和时间 \(t\)（正弦位置编码）构成。
  - 推理时：
    \[
    X_t=X_0+\int_0^t v_\theta(X_\tau,\tau\mid I_0,z^{(1)}_{st},\mathcal{X}_{<\tau})d\tau
    \]

- **总体损失**：
  \[
  \mathcal{L}=\mathcal{L}_{FaF}+\lambda\mathcal{L}_{ND}
  \]
  其中 \(\mathcal{L}_{FaF}\) 为条件流匹配损失：
  \[
  \mathcal{L}_{FaF}=\mathbb{E}\left[\left\|v_\theta(X,t\mid I_0,z^{(1)}_{st},\Xi_{0:t-1})-v(\Xi_t,X,t)\right\|^2\right]
  \]
  \(\lambda\) 在前 30k 步为 0.1，之后为 \(1.0\times 10^{-5}\)。

## 3. 实验设计

### 3.1 数据集与 benchmark

- **Fractal**（Google Robot）：87,212 样本，训练 84,212 / 验证 1,000 / 测试 2,000，平均 3.00 fps，词汇量 50。
- **Bridge V2**（WidowX）：60,064 样本，训练 57,064 / 验证 1,000 / 测试 2,000，平均 5.00 fps，词汇量 3,012。
- 两个数据集来自不同真实机器人平台，存在运动与视觉外观差异，用于跨具身评估。
- 预处理：
  - 图像 resize 到 256×256；
  - 微调 Robot-SAM 提取末端执行器掩码作为 alpha 通道；
  - 用 CoTracker3 跟踪点得到 \(\Xi_{0:T-1}\)；
  - 缺失语言指令用 Qwen2.5-VL 生成。
- **评估指标**：ADE（平均位移误差）、FDE（最终位移误差）、LTDR（小于 delta 比率，\(M=100\)）。ADE 为主指标，越低越好；LTDR 越高越好。仅在末端执行器区域评估，避免静止背景主导。

### 3.2 对比方法

- **Im2Flow2Act**：代表性语言条件机器人流生成基线。
- **Oracle**：真实实验中用 ground-truth robot flows 条件化策略，作为上界参考。
- 基线均在同一数据集上训练。
