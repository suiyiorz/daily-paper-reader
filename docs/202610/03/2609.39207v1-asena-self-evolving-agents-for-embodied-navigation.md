## 摘要
我们提出 ASENA，一个具身智能体系统，将通用编码智能体与机器人感知、计算、受监督执行以及持久经验连接起来。智能体可以编写和执行程序、检查记录的结果、修复故障，并复用笔记和可执行技能，同时保持其模型权重固定不变。我们进一步提出 ASENA-VLN，一种 4B 单目导航策略，作为该可编程系统中的一个可选工具。ASENA-VLN 使用共享的视觉-语言解码器预测身体坐标系下的轨迹，既用于长距离路线，也用于短时程行为；该解码器在路线指令、视觉问答以及一个新整理的由几何推导的原子导航任务数据集上训练。作为独立策略，ASENA-VLN 在 R2R 上达到 68.7%、在 RxR 上达到 70.2% 的最先进成功率。当与编码智能体集成时，学习到的导航在两项智能体基准上将 ASENA 的成功率提高 11 个百分点，同时减少执行时间。通过持久工作区演化和模拟器反馈，对重复出现的 100 任务子集进行十轮处理，进一步将 R2R 上的成功率从 72% 提高到 98%，将 RxR 上的成功率从 65% 提高到 89%。在具身问答任务上，ASENA 以更少的交互步骤达到最先进准确率。最后，在 Unitree G1 上的真实世界演示结合了搜索、视觉检查、空间推理和合成手势，且无需预先构建地图，展示了在线编程如何将机器人行为扩展到路线跟随和预定义技能之外。

## Abstract
We present ASENA, an embodied agent system that connects general-purpose coding agents to robot sensing, computation, supervised execution, and persistent experience. Agents can write and execute programs, inspect recorded outcomes, repair failures, and reuse notes and executable skills while keeping their model weights fixed. We further introduce ASENA-VLN, a 4B monocular navigation policy that serves as an optional tool within this programmable system. ASENA-VLN predicts body-frame trajectories for both extended routes and short-horizon behaviors using a shared vision-language decoder trained on route instructions, visual question answering, and a newly curated dataset of geometry-derived atomic navigation tasks. As a standalone policy, ASENA-VLN achieves state-of-the-art success rates of 68.7% on R2R and 70.2% on RxR. When integrated with a coding agent, learned navigation improves ASENA's success rate by 11 percentage points on both agentic benchmarks while reducing execution time. Through persistent workspace evolution and simulator feedback, ten passes over recurring 100-task subsets further improve success from 72% to 98% on R2R and from 65% to 89% on RxR. On embodied question answering, ASENA achieves state-of-the-art accuracy with fewer interaction steps. Finally, real-world demonstrations on a Unitree G1 combine search, visual inspection, spatial reasoning, and synthesized gestures without a pre-built map, illustrating how online programming extends robot behavior beyond route following and predefined skills.

## 1. 核心问题与研究动机

- **背景**：真实导航机器人不能只"到达终点"。例如用户要求"去看看自动售货机里有没有某件商品，然后回来告诉我"——机器人必须自行决定**去哪里搜索、识别什么物体、记住用户位置、如何回程并表达结果**。导航只是更大任务中的一环，下一步动作取决于机器人观察到什么。
- **现有方案的缺口**：
  - 学习式导航策略（VLN）只提供"运动能力"，无法自行决定"该检查什么、计算什么、如何沟通"；这些过程依赖新观测，且往往超出预定义技能集合。
  - 具身导航智能体多依赖固定策略与预定义技能，难以**在线编程、修复失败、积累经验**，在开放环境中适应能力受限。
- **论文主张**：编码智能体（coding agent）可以在任务执行过程中通过程序化接口访问感知、计算、仿真与动作，动态构建并修订这些流程；但物理部署还需要**与结果绑定的反馈、随程序变化仍然有效的安全防护、以及可持久保留有用流程的工作区**。
- **总体含义**：ASENA 把"通用编码智能体"接到"物理机器人"上，在**模型权重完全冻结**的前提下，通过持久工作区演化实现系统级自提升，并把学习式导航策略降格为可编程工具箱中的**可选工具**。

## 2. 方法论

### 2.1 系统总体架构（三层）

- **编码智能体层**：Codex / Claude Code 等通用编码智能体，以"写—运行—检查（Write · Run · Inspect）"循环工作，可读取工件、修复代码，模型权重固定。
- **ASENA 具身智能体层**：包含三块——
  1. **持久工作区 + 反馈**：程序、保留的笔记与可执行技能；
  2. **传感器与可调用运动工具**：ASENA-VLN（可选）、几何运动原语；
  3. **受监督执行**：间隙检查、仿真校验、运动限幅、人工确认门。
- **物理机器人层**：Unitree G1，配 360° 相机、LiDAR、机身 IMU、关节状态、里程计、可选麦克风；动作由 **SONIC 全身控制器**执行，可用扬声器做语音回应。
- **执行记录**：每次运行存为 **MCAP 记录**，把传感器/机器人状态与动作、操作员反馈、代码、可视化对齐，供回放、检查与复用。反思与工作区更新在**机器人运动被禁用**的状态下进行。

### 2.2 程序与物理反馈的耦合

- ASENA 把感知、控制、安全接口封装为**可调用的原子技能**（接近物体、穿过门洞、说话、做手势等）；智能体将这些操作与计算、交互逻辑组合成更大的可复用技能。
- 当动作与意图不符时，智能体可检查记录证据并修订程序；修订后的解决方案可被保留供未来任务使用。
- 导航可用两种方式：**几何工具**（显式路点与间隙推理）或**学习策略**（语言条件运动）。

### 2.3 分层安全防护

- **仿真在线校验**：合成手势先在 MuJoCo 中检查姿态连续性、关节/运动限幅、采样自碰撞；失败时把违反的约束返回给智能体修复。
- **人工确认门**：任何通过校验的运动在执行前都需操作员批准。
- **导航侧**：LiDAR 占据栅格用于路径规划与障碍间隙检查；独立防护层强制运动限幅，并在里程计过期或电量过低时拒绝指令。
- **执行侧**：心跳触发的停止与手动急停。
- 四层防护跨越**程序合成 → 仿真校验 → 人工授权 → 物理执行**。

### 2.4 从执行到可保留经验（工作区演化）

- 工作区在第 \(k\) 次修订记为 \(W_k = (N_k, S_k)\)：\(N_k\) 为笔记，\(S_k\) 为可执行技能。
- 固定权重的编码模型在求解任务时查阅该工作区；修订之间，另一个**固定权重的改进器（improver）**利用执行轨迹 \(\mathcal{T}_k\) 与反馈 \(f_k\) 更新工作区：
  \[
  W_{k+1} = I_{\varphi}(W_k, \mathcal{T}_k, f_k)
  \]
- **模型与控制器权重始终不变**。仿真中允许私有 worker 在轮次之间编辑工作区，但**冻结评估期间禁止写入**；G1 上则依据执行记录与可选操作员反馈修订技能，且每个修订程序仍须通过独立安全检查与操作员批准。

### 2.5 ASENA-VLN：可复用的视觉导航策略

- **基座与输出表示**：在轻量 **Qwen3-VL-4B-Instruct** 上扩展两套专用 token 词表——**轨迹 token** 与**像素目标 token**（共新增 1,343 个 token，其中 660 轨迹 token、683 像素目标 token），共享同一个自回归解码器。视觉问答沿用原始文本词表。
- **输入**：最多 8 帧前视历史（近期加权）+ 结构化 JSON 指令（含简明导航命令，可选终点位姿、锚定物体、运动约束），便于作为可调用工具使用。
- **输出**：最多 8 个累积的**身体坐标系路点**，每个为 \((x, y, \theta)\)；沿各轴使用固定分箱把轨迹 token 转成显式运动目标，**无需单独的连续动作头**。像素目标仅作辅助监督（不可直接执行，需额外运动规划器或仿真最短路径跟随器），因此**本文所有评测均使用轨迹 token 预测**。
- **原子导航数据**：在 MP3D 与 HM3D 上整理 **9 类原子导航任务**（按度量距离移动、旋转到目标朝向、从指定方向接近物体、对齐、进入房间、穿过门洞、沿走廊行进、跨楼层等），用测地距离、可见性与场景几何生成并校验，保证每条指令对应可行且可度量的运动；每条指令配路点轨迹与像素目标监督。
- **训练混合**：原子任务 + 短时程 ObjectNav

### 2.5（续）ASENA-VLN：训练混合与推理接口

- **训练混合**：原子任务 + 短时程 ObjectNav 混合采样。原子任务保证指令—动作映射的**可度量、可验证**；ObjectNav 片段提供"面向目标搜索"的组合性，使策略在长尾目标类别上仍能给出合理推进方向。两条数据流共享同一自回归解码器与损失，避免任务间表示漂移。
- **推理接口**：ASENA-VLN 被包装为一个**可调用的原子技能**（如 `vln.goto(instruction, constraints)`），返回身体坐标系路点序列供下游几何/安全层消费。它既不是唯一入口，也不是必需入口——智能体可在同一工作区内混用几何路点规划与学习策略，按子任务性质切换。
- **设计取舍**：把连续控制显式离散化为分箱 token，牺牲少量平滑性，换取三件事——与通用 VLM 词表的兼容、可解释的失败诊断（哪个 token 越界）、以及在编码智能体层面**可直接被程序读写与校验**的中间表示。

### 2.6 系统级自演化的评测协议

- **双轨评测**：一条是**冻结评估**（frozen evaluation），工作区在轮次间禁止写入，用于度量"当前工作区"的真实能力；另一条是**开放演化**（open-ended），允许改进器在轮次之间编辑工作区，用于度量"演化过程本身"能带来多少增益。二者分离是为了避免把"记住了这道题"误判为"学会了这类任务"。
- **对照条件**：通常需要区分（i）无工作区 / 空白工作区；（ii）有工作区但禁用改进器；（iii）完整 ASENA。这样可以把增益归因到**工作区内容**而非仅仅"多跑了几轮"。
- **物理侧协议**：G1 上的每次修订都必须重新走完"程序合成 → 仿真校验 → 操作员授权 → 物理执行"四层防护；操作员反馈作为可选信号进入 \(f_k\)，但不作为唯一监督来源。
- **可追溯性**：MCAP 记录使失败可回放、修订可对比，构成"经验保留"的证据链，也是后续技能复用的前提。

## 3. 实验与结果（结构性描述）

- **原子导航能力**：ASENA-VLN 在 9 类原子任务上按类别分别报告成功率与路径效率，用于验证"指令—路点"映射的可靠性；这一层是系统的基础能力上限。
- **ObjectNav / 组合任务**：在 MP3D、HM3D 等场景中评估短时程目标搜索，考察策略与几何规划器混合使用时的表现。
- **系统级任务**：在真实 G1 上执行"检查某物体并回报"这类**跨感知—决策—运动—语言**的复合任务，观察编码智能体能否在失败后定位原因、修订程序并复用。
- **演化增益**：在冻结评估下比较不同工作区版本的性能曲线，检验 \(W_{k+1} = I_\varphi(W_k, \mathcal{T}_k, f_k)\) 是否带来**单调或近单调**的提升，以及提升是否集中在特定任务族上。

## 4. 关键发现与方法论意义

1. **"冻结权重 + 可写工作区"是一条可行的系统级自提升路径。** 提升不来自梯度更新，而来自程序、笔记与技能库的持续修订；这让机器人在不重训模型的前提下积累经验。
2. **学习式导航策略应当被"降格"为工具，而非系统骨架。** 当策略以原子技能形式暴露给编码智能体后，它只在"该往哪走"这一子问题上发力，而"该做什么、检查什么、如何回报"由上层程序承担，职责边界更清晰。
3. **安全防护必须分层且与程序变更解耦。** 仿真校验、人工门控、导航侧间隙检查与执行侧急停分别在不同抽象层拦截错误，使得**智能体可以自由改写上层逻辑而不削弱底层安全性**。
4. **可追溯的执行记录是"经验"的载体。** MCAP 对齐了感知、状态、动作、代码与反馈，使失败可被程序化诊断，也使用户/操作员的纠正能转化为可复用的技能修订。
5. **离散化中间表示（token 路点）兼顾兼容性与可检查性。** 它让通用 VLM 与物理机器人之间的接口保持"文本化、可校验、可编辑"。

## 5. 局限与开放问题

- **评测规模与场景多样性**：真实机器人实验通常受限于场景数量与试验次数，泛化性结论需要谨慎外推。
- **改进器的可靠性**：工作区演化依赖改进器对轨迹与反馈的正确解读；若反馈稀疏或噪声大，可能积累错误技能（"负向经验固化"）。
- **人工门控的可扩展性**：操作员确认提升了安全性，但在长时程、高频动作场景下可能成为吞吐瓶颈。
- **表示层损失**：固定分箱的路点离散化在精细操作与高速运动下可能不足；像素目标 token 目前仅作辅助监督，尚未形成闭环。
- **安全边界的形式化**：四层防护是工程化的组合，而非形式化证明；对未预见的新型指令，其覆盖性仍待验证。
- **跨任务技能复用**：工作区中技能的抽象层级、命名与检索机制如何影响复用效率，仍是有待系统研究的开放问题。

## 6. 结论

ASENA 的核心贡献不在于提出更强的导航模型，而在于给出一种**把通用编码智能体安全地接入物理具身系统**的架构范式：模型权重冻结，能力增长体现在可执行、可校验、可追溯的工作区演化中；学习式导航被封装为可编程工具箱里的一个可选工具；安全性通过跨抽象层的四重防护与"程序变更解耦"得以维持。其方法论意义在于把具身智能的"学习"问题部分转化为**软件工程与经验管理**问题，并提供了一个可回放、可归因、可迭代的评测骨架。
